## 0-2. 素材の読み方（Phase 1・2 の共通入口）

素材は「要約する」ために読むのではない。**Phase 1（相手）と Phase 2（事実）の材料を抜くために読む。**
同じ議事録から、**相手の感情**と**検証可能な事実**という別種のものを取り出す。

| 素材 | Phase 1（相手モデル）へ抜くもの | Phase 2（事実）へ抜くもの |
|---|---|---|
| **議事録・打合せメモ** | 🔴 **相手が実際に使った言葉**（認識層の判定根拠）、質問の内容、渋った箇所、繰り返し出た話題 | 数値、固有名詞、日付、体制、既存契約 |
| **メールスレッド** | 返信の速さ・文面の温度、誰がCCにいるか（＝意思決定構造） | 合意済み事項、依頼の原文、期限 |
| **既存の提案書・資料** | 過去に何を提案され、なぜ通らなかったか（＝過去の失敗＝懸念#5） | 前提条件、単価、範囲の定義 |
| **Excel・データ** | — | 数値そのもの。**集計方法と対象期間を必ず確認**（そのまま使うと誤る） |
| **相手のHP・IR・求人** | 対外的に何を言っている会社か、いま何に投資しているか | 従業員数、拠点、事業内容、沿革 |
| **業界レポート・公的統計** | 相手が「うちは特殊」と言う根拠になりうる論点 | 一般値（確度＝中で記録する） |

**読むときの3つの禁止**

- ❌ 素材の順番のままメモを作る → 素材の構造はこちらの都合。**抜くのは要素であって順序ではない**
- ❌ 事実と、書き手の解釈を区別せずに写す → 議事録の「〜が課題だと思われる」は**事実ではない**
- ❌ 素材に無いことを補って書く → 不足は Phase 2-3 の「足りない事実」へ回す

**素材が足りない／そもそも無い場合**
Phase 1 は公開情報（HP・求人・IR・業界動向）で埋められる。Phase 2 は埋められない。
**事実が無い状態で作れるのは型E（関係構築型）だけ**と割り切る。

### 🔴🔴 例外 — 面識のない相手へ、一方的に送る場合（2026/9/12 本人指定）

型Eの「売り込まない・覚えてもらう」は、**送る相手には効かない**。門外漢の手紙は無視されるだけである。

> **本人の言葉（2026/9/12）**
> 「聞くとかヒアリングとかでは最悪、あと電話一本というのも最悪、**知らないやつからいきなりそんなことを聞かれても答えない**。
> 相手の業界や状況を**想定しきったうえで、刺さる提案をする。刺しに行けば多少ズレていても、そうではないというレスポンスをくれる。
> 門外漢の手紙は完全に無視される**」

| ❌ やらない | ⭕ やる |
|---|---|
| 「現状をお聞かせください」を主題にした資料 | **こう見立てました、だからこうします**と言い切る |
| 送る前に「まず電話で状況を確認する」 | 送る前に**業界を調べ尽くして、想定を固める** |
| 分からないことを相手に質問する | 分からないことは**想定で埋め、想定だと分かる形で出す** |
| 「ヒアリングさせてください」という次の一歩 | 「この見立てで進めます」という次の一歩 |

🔴 **ズレを恐れて曖昧にするのが最悪。** 具体的に刺せば、外れていても「うちはそうじゃない」と返ってくる。
**その否定が、面識のない相手から得られる唯一の反応**であり、そこから会話が始まる。曖昧な問いかけは否定する対象すら無く、捨てられる。

#### 負けは「外すこと」ではなく「門外漢だと見抜かれること」

| 見抜かれる書き方 | 業界を知っている書き方 |
|---|---|
| 「積算はExcel、日報は紙で管理されていると思われます」（**どの会社にも当てはまる**） | その業界固有の工程・書類・規制・商習慣の名前で書く |
| 一般的な業務フロー（受注→作業→請求） | その業界で実際に使われている呼び名と順序 |
| 相手の業種を言い換えただけの課題 | その業界の人しか知らない詰まりどころ |

**一般論を固有名詞で包んでも、固有の提案にはならない。** 相手は1行目で見抜く。

#### 書く前にやること（相手にではなく、業界に対して）

1. **受注構造を調べる。** 誰が誰に発注し、何で決まるのか（価格・実績・資格・指名・入札・紹介・関係）
2. **業務と書類の名前を覚える。** 工程・帳票・許認可・安全書類・業界共通のシステム
3. **よくある詰まりを調べる。** 業界紙・団体資料・行政の調査・同業の求人票の業務内容
4. **相手固有の公開情報を、その業界の文脈に置いて読む。** 同じ事実でも意味が変わる

⚠️ **1〜3を飛ばして4だけやると、必ず門外漢の手紙になる。**
実例（2026/9/12 大光電気工業）: 「HPが無い」を課題と読んだが、**官公庁の入札で受注する会社にHPが不要なのは合理的な判断**だった。業界の受注構造を先に押さえていれば、主題そのものが変わっていた。

⚠️ **既存顧客・紹介された相手・面談が決まっている相手には、この例外を適用しない。** 聞ける関係があるなら聞いたほうが速い。

📌 1社ごとの検討で使う様式は `プロジェクト/20260911_HP起点営業_都内中小企業開拓/テンプレート/提案戦略メモ_雛形.md` §0「業界の見立て」。

# Phase 1 — 相手モデル（相手の頭と心を先に作る）

> ここが弱いと、以降どれだけ論理を積んでも刺さらない。**最優先で時間を使う工程。**

## 1-1. 🔴 認識の5層 — 相手がどこにいるかで、ストーリーの起点が変わる

**最も多い失敗は「相手がL3にいるのに、L0向けの資料を作ること」。**
相手はすでに知っていることを長々と説明され、「この人は分かっていない」と判断する。信頼はここで失われる。

| 層 | 相手の状態 | 起点にすべきこと | やってはいけないこと |
|---|---|---|---|
| **L0** 知らない | 課題の存在自体を認識していない | 事実を見せて存在を知らせる | いきなり解決策を出す |
| **L1** 知っているが自分ごとでない | 一般論としては知っている | **自社の数字・自社の固有名詞に翻訳する** | 一般論を繰り返す |
| **L2** 自分ごとだが優先度が低い | 困ってはいるが後回し | **放置コストと期限**を示す | 課題を再説明する（くどい） |
| **L3** 優先度は高いが手段が分からない | やりたいが決められない | **選択肢と推奨**を出す | 課題提起（相手はもう知っている） |
| **L4** 手段も決まり、承認だけが要る | 実行判断待ち | 稟議に必要な材料をそろえる | 説得する（不要どころか邪魔） |

**判定のしかた**: 打ち合わせで相手が使った言葉を見る。
「そんなこともあるんですね」＝L0〜L1／「うちもそうなんですよ」＝L2／「どこに頼めばいいのか」＝L3／「上に上げる資料が要る」＝L4。

## 1-2. 感情の棚卸し

事実は感情を経由してしか届かない。次を、**根拠とセットで**書く。

| 感情 | 問い |
|---|---|
| 期待 | 何を期待しているか。それは実現可能か |
| 不安 | 何が怖いか。失敗すると誰に何を言われるか |
| 警戒 | 売り込まれることをどの程度警戒しているか |
| 面倒 | 自分の作業が増えることをどう思っているか |
| 諦め | 過去に同種の試みが失敗していないか |

## 1-3. 🔴 懸念の類型（8つ）— チェックリストとして必ず全部当てる

Phase 4 の**判定条件**（ループを止めてよいかの物差し）になるので、**「該当なし」も含めて8つ全部を埋める**。
書き方は、**相手が実際に言いそうなセリフ**で書く。要約すると後で使えない。

| # | 類型 | 相手が言いそうなセリフの例 |
|---|---|---|
| 1 | **お金** | 「そんな予算はない」「費用対効果が見えない」 |
| 2 | **時間** | 「今期はもう動けない」「決算が終わってからで」 |
| 3 | **手間** | 「こっちの作業がどれだけ増えるのか」 |
| 4 | **社内の反発** | 「現場が嫌がる」「担当が自分の仕事を取られると思う」 |
| 5 | **過去の失敗** | 「前も同じことをやって続かなかった」 |
| 6 | **当社への不信** | 「1人の会社で大丈夫なのか」「途中で投げないか」 |
| 7 | **タイミング** | 「今じゃない」「もう少し様子を見たい」 |
| 8 | **「うちは特殊」** | 「うちの業界は事情が違う」「他所の事例は当てはまらない」 |

> ⚠️ 6と8は当社の状況上ほぼ必ず出る。**代表者1名の会社であること**と、**相手が中小企業経営者であること**が理由。
> 出ると分かっているものは、最初からストーリーに組み込んでおく。

## 1-4. 意思決定の構造

| 役割 | 確認すること |
|---|---|
| **決裁者** | 最終的に決めるのは誰か。目の前の相手か、その先か |
| **影響者** | 決裁者が意見を聞く相手は誰か（顧問税理士、古参社員、家族） |
| **実務者** | 実際に手を動かすのは誰か。その人は歓迎しているか |
| **反対者** | 反対しそうな人は誰か。その理由は何か |
| **資料の行き先** | この資料は誰の手に渡るか。**渡るなら一人歩き耐性が必須**（ドクトリン原則7） |

### 🔴 同席者がいて、認識層が違う場合

中小企業では「社長＋実務担当」の同席が普通で、**両者の認識層はたいてい違う**（社長L1・担当L3 など）。
このとき**両方に合わせようとすると、どちらにも刺さらない資料になる。**

| 原則 | 内容 |
|---|---|
| **本編は決裁者に合わせる** | 決めるのは決裁者。本編の認識層は決裁者で決める |
| **実務者向けはAppendixへ回す** | 詳細・手順・技術的裏付けは本編に入れず、聞かれたら出す |
| 🔴 **実務者を否定しない** | 実務者が現状の担当者である場合、課題の指摘が**その人への批判に聞こえる**。「体制の問題であって能力の問題ではない」と明示的に言う（懸念#4 社内の反発の予防） |

同席者ごとに、**この場で何を持ち帰ってほしいか**を1行ずつ書き分ける。

## 1-5. 環境

業界動向／競合の動き／法規制・制度／時期要因（決算期、繁忙期、補助金の公募時期）。

- 分担: 調査と洗い出しはAI。**相手の温度感・人物像の補正は本人**（面談で得た情報はAIが持っていない）

# Phase 2 — 事実の整理（ストーリーの土台をつくる）

## 2-1. 🔴 事実・分析・主張の三層分離

**この分離が、原則5（事実を曲げない）を手順として担保する仕組みである。**
混ぜて書くと、無意識に「盛った表現」が混入し、それが商談の場で崩れる。

| 層 | 定義 | 例 |
|---|---|---|
| **事実（F）** | 検証可能。出典を示せる | F1: 運用担当は1名（8/20 議事録） |
| **分析（A）** | 事実から論理的に言えること | A1: 退職時に業務が止まりうる（F1より） |
| **主張（C）** | 当社の意見・提案 | C1: 6か月以内に着手すべき |

**記録形式**

| # | 内容 | 層 | 出典 | 確度 |
|---|---|---|---|---|
| F1 | 対象業務の担当は1名 | 事実 | 2026/8/20 議事録 | 高 |
| A1 | 退職時に業務が止まるリスクがある | 分析 | F1 | 高 |
| C1 | 6か月以内に着手すべき | 主張 | A1＋一般的な引継期間 | 中 |

## 2-2. 確度と、それに対応する表現

**確度を超えた断定をしない。** 確度は表現の強さを縛るために付ける。

| 確度 | 条件 | 使ってよい表現 |
|---|---|---|
| **高** | 一次資料がある／本人発言の記録がある | 「〜です」「〜が確認されています」 |
| **中** | 推定・業界一般値・当社の経験値 | 「〜と見込まれます」「一般に〜とされています」 |
| **低** | 未確認・伝聞 | **本編に載せない。** どうしても要るなら「未確認ですが」と明記 |

## 2-3. 足りない事実を先に洗い出す

**「これが無いとストーリーが成立しない」事実を特定し、先に取りに行く。**

- 本人に聞けばわかること → 質問リストにして**まとめて1回で聞く**（小出しにしない）
- 調べればわかること → **AIが調べる**（社長に投げ返さない）
- どうしても得られないもの → **その前提でストーリーが成立するか**を確認し、成立しないなら組み替える

🔴 **不足を想像で埋めない。** 埋めた瞬間、それは事実の捏造になる。

## 2-4. 🔴 出してよい情報の線引き（守秘・単価）

**顧客に渡す資料は社外へ出る。** Phase 2 の段階で線引きを済ませる（作ってから消すと、構成ごと崩れる）。

### 他社（既存顧客）の情報

当社の実績はほぼ **NSSOL 1社**であり、型A・型Bの「**なぜあなたに頼むのか**」に答えるとき必ずここに触れる。

| 書ける | 書けない |
|---|---|
| 「大手SIer向け」「通信キャリア領域」までの**抽象度** | 🔴 **顧客名・システム名・案件固有の内容** |
| 担った役割・規模感・そこで得た知見 | 単価、契約条件、体制、社内固有の呼称 |
| 公開情報として自社HPに既に載っている内容 | 議事録・成果物から引いた具体 |

- この抽象度は `プロジェクト/20260823_LinkedIn開設と運用/方針計画_20260823.md` §7 で確立した運用を踏襲している
- ⚠️ **`スペック/経理/受注契約.md` に秘密保持条項が記録されていない**（準拠契約＝業務委託基本契約及び付帯する覚書の側にある）。
  **原本を確認して条項を記録するまでは、上表の抽象度を上限として扱う**

### 自社の単価・見積

- 費用スライドに書く金額は、**`スペック/経理/受注契約.md` と `ジャーナル/経理/月次見積/` の実績と整合させる**
- 🔴 **その場で単価を作らない。** 新サービスで実績がない場合は、根拠（工数×時間単価）を Phase 2 に事実として登録してから書く
- **前提条件を必ずセットで書く**（対象範囲・訪問回数・交通費・税込税別）。前提のない金額は後で必ずもめる

### 第三者の著作物

- 図表・データを引用する場合は**出典を明記**し、改変しない
- 有償レポートの内容をそのまま転載しない

# Phase 3 — ゴール定義（相手の到達点を決める）

## 3-1. Before / After 認識表

| 観点 | Before（現在の認識） | After（到達させたい認識） |
|---|---|---|
| 課題認識 | 「困ってはいるが緊急ではない」 | 「今期中に手を打つべき事業リスクだ」 |
| 解決可能性 | 「うちの規模では無理」 | 「この規模でも段階的にやれる」 |
| 当社への信頼 | 「よく知らない会社」 | 「この人になら任せられる」 |

## 3-2. 相手が「自分の言葉で言えるようになること」（1〜3個）

日本企業では、聞き手はほぼ必ず社内の別の誰かに説明する。
**その場で相手の口から出てほしいフレーズ**を、実際のセリフとして書く。

> 例: 「担当が1人しかいなくて、辞めたら止まるんだよ。今のうちに手順を残しておきたい」

これが書けないなら、ストーリーはまだ相手のものになっていない。

## 3-3. 成功指標

その場で何が起きたら成功か。**「検討します」は成功ではない。**

| レベル | 例 |
|---|---|
| 最低 | 次回の打ち合わせ日程が決まる |
| 標準 | 相手が社内の誰に相談するかを口にする／見積依頼が出る |
| 最良 | その場で範囲と時期の合意ができる |

## 3-4. 🔴 ゴールは相手の到達点であって、こちらの獲得物ではない

「受注する」はこちらの獲得物。ゴール欄に書くのは**相手の心理状態**である。
獲得物は成功指標（3-3）のほうに書く。ここを混ぜると、ストーリーが売り込みに傾く。

## Phase 3 の出力とゲート

- 出力: `ワークシート雛形/03_ゴール.md`
- ゲート: 🔴 **本人が確定する。** 何を勝ちとするかは経営判断であり、AIが決めてよい範囲を超える

# Phase 4 — ストーリー（タイトルとメッセージを固める）

> **このフェーズで固めるのは、全スライドの「タイトル」と「メッセージ」だけ。**
> コンテンツ（何が載るか）とテンプレートは Phase 5 で決める。

## 4-1. 🔴 まず「型」を選ぶ — 型は Phase 1 の認識層から決まる

型を選ばずに書き始めると、必ず「全部盛り」になって持ち時間を超える。

| 型 | 使う相手 | ゴールの性質 |
|---|---|---|
| **A 問題提起型** | L0〜L1 | 課題を自分ごとにさせる |
| **B 手段提示型** | L2〜L3 | 進め方を納得させる |
| **C 選択支援型** | L3 | 決めさせる |
| **D 報告・承認型** | L4 | 承認を得る |
| **E 関係構築型** | 層が不明・初回接触 | 覚えてもらう（売り込まない） |

### 型A 問題提起型（L0〜L1）— 🔴 これが基準の8問

```
Q1 これは自分に関係あるのか      Q5 うちでも本当にできるのか
Q2 なぜそう言えるのか            Q6 いくらかかるのか
Q3 どのくらい深刻なのか          Q7 なぜあなたに頼むのか
Q4 どうすればいいのか            Q8 まず何をすればいいのか
```
⚠️ **Q2を飛ばさない。** Q1の直後に「本当か」が必ず来る。ここで事実を出せないと以降が全部疑われる。
⚠️ Q3は「**放置するとどうなるか**」まで踏み込む。深刻さは現状の描写ではなく、**放置した先**で伝わる。

> 📌 **この8問は `テンプレート/index.html` の索引軸と同一。** 型Aで作った設計表は、そのまま型を引ける。
> 型B〜Eは問いが異なるため、**下記「型ごとのテンプレート対応」**で引く。

### 型B 手段提示型（L2〜L3）

```
Q1 何を提案するのか（結論先出し） Q5 いくら・いつまでか
Q2 なぜそれで解決するのか        Q6 失敗したらどうなるのか
Q3 うちでもできるのか            Q7 まず何をすればいいのか
Q4 どう進めるのか
```
⚠️ **課題の説明に時間を使わない。** 相手はもう知っている。1枚で確認して先へ進む。

### 型C 選択支援型（L3）

```
Q1 選択肢は何か                  Q5 その根拠は何か
Q2 何を基準に比べるべきか         Q6 選ばなかった案のリスクは
Q3 それぞれどうなのか             Q7 いつまでに決めればいいのか
Q4 あなたの推奨はどれか
```
🔴 **本体はQ2（評価軸の提示）。** 選択肢を並べるだけの資料は、相手に宿題を渡しているのと同じ。
軸を出し、推奨を明示し、選ばなかった案のリスクまで言うのがこの型の仕事。

### 型D 報告・承認型（L4）

```
Q1 承認いただきたいことは何か（結論）  Q4 問題は何か・どう対処するか
Q2 現在どこまで進んでいるのか          Q5 承認が要るのは何か
Q3 計画との差分は何か                  Q6 承認しないとどうなるか
```
⚠️ **悪い情報を後ろに置かない。** 差分と問題は前半で出す。後出しは信頼を最も強く損なう。

### 型E 関係構築型（初回接触・交流会後など）

```
Q1 何者か        Q3 誰の役に立ってきたのか    Q5 次に何が起きるのか（軽い一歩）
Q2 何ができるのか  Q4 自分と関係がありそうか
```
🔴 **提案しない。** ゴールは「必要になったときに思い出してもらえる状態」。
売り込むと、この型は逆効果になる。

## 4-2. コアの問いを1つに決める

**この資料が答える、相手の問いを1つだけ書く。**

> 例: 「担当が1人しかいない状態を、いつ・いくらで・どう直せばいいのか」

- 問いが2つ以上あるなら、**それは2本の資料である**（1回の商談で2つは解けない）
- 問いが書けないなら Phase 1 か Phase 3 に戻る

あわせて、この問いに対する**答え（コアメッセージ）を1文**で書く。
**書けなければ、まだ設計に入ってはいけない。**

## 4-3. 枚数を決める

🔴 **枚数は、持ち時間から先に決める。作りながら増やさない。**

| 持ち時間 | 説明に使える時間（7割） | 枚数の目安 |
|---|---|---|
| 15分 | 約10分 | **5〜8枚** |
| 30分 | 約20分 | **8〜12枚** |
| 60分 | 約40分 | **16〜18枚** |

**形式で補正する**（Phase 0 のインテークで聞いた「対面／オンライン／送付のみ」を、ここで使う）。

| 形式 | 補正 | 理由 |
|---|---|---|
| **対面** | 基準どおり | 相手の反応を見て話す速度・深さを調整できる |
| **オンライン** | 🔴 **2〜3枚減らす** | 画面共有では1枚あたりの滞在が長く、相手の反応が読めない。**枚数より1枚の完結性**を優先する |
| **送付のみ** | 枚数は据え置き。**要約ページ必須＋Appendix厚め** | 対話がないため、相手は問いの連鎖を**自分で辿る**。入口（要約）と逃げ道（Appendix）の両方が要る |

**絶対上限は18枚。** 超える選択肢はない。

🔴 **枚数は成果ではない。** 8枚で相手が動くなら8枚が正解であり、16枚にするのは相手の時間を奪う劣化である。

## 4-4. 🔴 タイトルとメッセージの通しを書く（Phase 4 の本体）

**この工程の成果物は、全スライドぶんの「タイトル」と「メッセージ」の一覧である。**

| | 何を書くか | 形 |
|---|---|---|
| **タイトル** | **そのスライドが何について書いてあるか。事実・事柄の名前** | 体言中心・25文字目安・1行 |
| **メッセージ** | **そのスライドで、聞き手に理解してほしいこと。主張** | 文。1〜2文。敬体 |

> 🔴 **両者は一致してはいけない。** タイトルは「何の話か」、メッセージは「何を理解してほしいか」であり、役割が違う（→ `ドクトリン.md` 原則1）。

### 書き方

| # | タイトル（何についての1枚か） | メッセージ（理解してほしいこと） |
|---|---|---|
| 1 | 〈資料名〉 | （表紙） |
| 2 | エグゼクティブサマリー | 〈結論を1文で〉 |
| 3 | 〈事柄の名前〉 | 〈主張〉 |

- **同じ形の連続する数枚は、タイトルの形を揃える**（例:「メンバーの担当範囲の変化」「リーダーの担当範囲の変化」）。**同型の並びであることが、目次だけで分かる**
- **メッセージの文型も、その並びの中で揃える**（例:「AからBになります」を3回）。文型を崩すと、並びが読み取れなくなる
- 🔴 **1枚に2つのメッセージを載せない。** 載りそうになったら、それは2枚である

### 🔴 ここで決めないこと

**コンテンツ（何が載るか）とテンプレートは、Phase 5 で決める。**
ここで図表を考え始めると、**言いたいことより描けるものに引っ張られる。**

## 4-5. 感情曲線を設計する

問いの連鎖は論理の設計だが、**同時に感情の設計でもある**。

```
  不安 ──▶ 直視 ──▶ 「打つ手はある」 ──▶ 「うちでもできる」 ──▶ 期待
```

🔴 **不安を作ったまま終わらせない。** 危機感だけを煽って解決策を薄くすると、相手は「怖いから何もしない」に倒れる。
**必ず「管理可能なもの」に着地させる**（リスクを挙げたら、必ず対策とセットで出す）。

## Phase 4 の出力とゲート

- 出力: `ワークシート雛形/04_ストーリー.md`（**全スライドのタイトルとメッセージの通し表**）
- ゲート: 次の**2つの通読テストと、判定4項目**がすべて○

### 🔴 通読テストは2つある

| | テスト | 通る条件 |
|---|---|---|
| **ゲート1（目次）** | **タイトル列だけ**を上から読む | **何を説明する資料かが分かる** |
| **ゲート2（話）** | **メッセージ列だけ**を上から読む | **1本の話として通る** |

⚠️ **片方だけ通っても不合格。** ゲート1だけなら主張のない箱の羅列、ゲート2だけなら目次の作れない資料である。

### 判定4項目

**判定するのは相手だが、作成時点で相手はいない。したがって Phase 1 の相手モデルでシミュレートする。**

- [ ] **①** 4-2 のコアの問いに、答えているか
- [ ] **②** 各枚を見た相手が次に抱く問いが、**資料内のどこかで解けている**か（Appendix含む）
- [ ] **③** 懸念8類型のうち、**この相手に効くもの**が解けているか（該当なしと判断したものは記録する）
- [ ] **④** 通しで見て、Phase 3 の **After 認識に到達する**か

### 🔴 矛盾検査（メッセージ列を、主語ごとに縦に読む）

**同じ主語について、違うことを言っていないか。**

- [ ] 🔴 **時制が混ざっていないか**（「もうそうなっている」と「これからそうなる」を同じ相手について言っていないか）
- [ ] 同じ語を、違う意味で使っていないか
- [ ] あるページで前提にしたことを、別のページで否定していないか

⚠️ **ゲート2（話として通るか）だけでは、これは出ない。** 通して読むと流れてしまうため、**主語ごとに縦に拾って突き合わせる。**

### 通らない場合の戻り先

**枚数を増やして解決しない。** 次のどれかに戻る。

| 症状 | 原因 | 戻り先 |
|---|---|---|
| 論点が多すぎて収まらない | 1回の商談で扱う問いが2つ以上ある | **4-2 へ戻り、資料を分割する** |
| 根拠が薄くて納得に届かない | 事実が足りない | **Phase 2 へ戻る** |
| 相手の認識を動かしきれない | 1回で到達させようとしている | **Phase 3 へ戻り、ゴールを分割する**（今回は「次アポ」までに下げる等） |

⚠️ **タイトルとメッセージは Phase 4 で確定している。ここで書き換えない。**
🔴 **本フェーズの仕事は、各スライドに「何が載るか」を決め、それに合う型を当てることである。**

## 5-1. やること

| # | 作業 | 注意 |

| 1 | Phase 4 の通し表を、設計表の行に**そのまま**移す | 行数＝枚数。**ここで足さない・減らさない** |

| 5 | Appendix を切り出す（→ 5-4） | 本編から外すのであって、本編に足すのではない |

## 5-2. 🔴 コンテンツを決める（設計別紙）

**1スライド1ブロック**で書く。表に押し込むと書ききれない。

| 欄 | 定義 | 出どころ |
|---|---|---|
| **タイトル** | そのスライドが何について書いてあるか | 🔴 **Phase 4 から転記**（考え直さない） |
| **メッセージ** | 聞き手に理解してほしいこと | 🔴 **Phase 4 から転記**（考え直さない） |
| **コンテンツ** | 🔴 **そのスライドに載るものの、完成形** | **ここで決める**（→ 5-2-1） |
| **支える理由** | 🔴 **その中身が、メッセージをどう支えるか**（1〜2行） | **ここで書く**（→ 5-2-2） |
| **検算** | 🔴 **中身が成り立っているかの確認** | **ここでやる**（→ 5-2-3） |
| **テンプレート** | T-01〜T-16 のどれか | **ここで決める**（→ 5-3） |

---

### 5-2-1. コンテンツは「完成形」で書く

**制作者が迷わず作れる状態まで書く。** 判定基準は **「これを読んだ別の人が、同じスライドを作れるか」**。

| 種類 | 書くこと |
|---|---|
| **表** | 🔴 **列名と全セルの中身。** 「3列6行の表」だけでは足りない |
| **対比** | 🔴 **左右のラベルと、全項目。** 項目数を左右で揃える |
| **図・構造** | 🔴 **各要素のラベルと、要素間の関係（矢印の向き・意味）** |
| **カード** | 🔴 **見出しと本文の全文** |

| | 例 |
|---|---|
| ⭕ | 3列6行の表。列は〈年代〉〈新人に頼んできたこと〉〈そのうち自動化されたところ〉。行は1965／1985／1995／2005／2015／2025。**各セルの中身を全部書く** |
| ❌ | 年表を示す／対比を見せる／3点を挙げる |

---

### 5-2-2. 🔴 「支える理由」を必ず書く

**その中身を選んだ理由を、1〜2行で書く。**

> 例（年表のページ）: 「各行で **頼んでいた仕事の一部** が自動化されてきたことを示し、最下段だけ **全部** が自動化されたことで、『今回が到達点である』を見せる」

⚠️ **書けないなら、そのコンテンツはメッセージを支えていない。** 図表を先に決めて理由を後から付けない。

---

### 5-2-3. 🔴 検算 — 中身が成り立っているかを確かめる

**ここを飛ばすと、因果の壊れた図表が検査を全部通り抜ける。**
`fit` も言葉遣い検査も突合も、**中身の正しさは見ていない。**

#### 表・対比の検算（1行ずつ当てる）

- [ ] 🔴 **列どうしの対応が成り立っているか。** 「AだからB」と読める行になっているか
- [ ] 🔴 **同語反復になっていないか**（左の語が右にそのまま出ていないか）
- [ ] 🔴 **抽象度が列で揃っているか**（左が作業名、右が製品名、のようにずれていないか）
- [ ] 行の並びに理由があるか（時系列・大小・重要度）
- [ ] **左右の項目数が揃っているか**（対比の場合）

#### 🔴 流用したものは、必ず検算する

> **他の資料・前の版から図表を持ってきたら、そのままにしない。**
> **今回のメッセージに対して成り立つかを、1行ずつ当て直す。**

⚠️ **これが最も起きやすい抜け。** 前の版で通っていた表は「通ったことがある」だけであり、**今回のメッセージを支える保証はない。**

## 5-3. テンプレートを当てる

**コンテンツが決まってから、それを載せられる型を選ぶ。**

## 5-4. 本編と Appendix の切り分け

| 本編に入れる | Appendix に回す |
|---|---|
| 問いの連鎖に載っているもの | 聞かれたら出す詳細データ |
| 相手が自分ごととして必要なもの | 網羅性のために付けたくなったもの |

🔴 **「念のため入れておく」は本編を殺す。** 迷ったら Appendix。

## 5-5. 時間配分

- 想定秒数の合計が持ち時間の**7割以下**に収まっていること（残り3割は相手の質問と反応のため）
- 収まらないなら、枚数を削る。**話速を上げて詰め込まない**（逐次対話が成立しなくなる）
- 目安: 表紙10秒／要約60秒／通常ページ60〜90秒／数値・比較ページ90〜120秒

### 要約ページを入れるかどうか

| 入れる（必須） | 入れなくてよい |
|---|---|
| 資料が**社内回覧される**（Phase 0 で確認済み） | 5枚以下、かつ対面、かつ回覧されない |
| **送付のみ**の形式 | |
| **16枚以上**の資料 | |

要約ページは「**結論1文 ＋ 理由3点**」。理由は3つに絞る（4つ以上は覚えられない）。
🔴 **要約は本編の1枚目を貼り直したものではない。** 全体を圧縮して作り直す。

## 5-6. 想定問答とスピーカーノート

ドクトリン原則6（話すことと書くことを分ける）を、ここで実体にする。

**想定問答は発明しない。Phase 1 の懸念8類型から機械的に作る。**

| 懸念の扱い | 置き場所 | 判断基準 |
|---|---|---|
| **本編に入れる** | 懸念つぶしページ | Phase 4 の判定③で「この相手に効く」と判定したもの（上位1〜3個） |
| **ノートに置く** | スピーカーノート | それ以外。聞かれたら答える |
| **Appendix にする** | Appendix | 回答に**データや図が要る**もの |

各ページのノートに書くもの: ①口頭で足す肉付け ②このページで想定される質問と回答 ③次のページへの渡し方。

⚠️ **ノートに書いた内容をスライド本文へ移さない。** 移した瞬間、相手は読み始めてこちらの話を聞かなくなる。

## 5-7. 🔴 レビューの出し方（本人の時間を10分以内にする）

本人に渡すのは**設計表と設計別紙、そして次の3点だけ**。

1. 相手の認識層（L0〜L4）と、選んだストーリーの型
2. Phase 3 のゴール（After認識・自分の言葉で言えること・成功指標）
3. **確認してほしい点を名指しで3つ以内**（例:「相手の懸念に『社内の反発』を入れましたが、実際はどうですか」）

「全体を見てください」と丸投げしない。**判断すべき箇所を絞って出すのが秘書の仕事。**

⚠️ **設計表だけを出さない。** 設計表は骨格しか示さないため、「構成は良い」で通ってしまう。
🔴 **中身の合意は設計別紙でしか取れない。**

## 認識層が上がっていなかった場合

前回の資料が効かなかったということ。**同じ資料を厚くしても結果は変わらない。** 次のどれかを疑う。

| 疑うこと | 対処 |
|---|---|
| 認識層の判定を誤っていた | 1-1 の判定方法で見直す |
| 懸念を解けていなかった | 実施記録の「想定外だった懸念」を懸念リストへ追加し、今回それを中心に据える |
| ゴールが高すぎた | Phase 3 でゴールを下げる（今回は次アポまで、等） |
| そもそも相手に必要がない | 🔴 **撤退も選択肢。** 資料を作り続けることが目的ではない |

## よくある詰まりどころ

| 症状 | 原因 | 対処 |
|---|---|---|
| 素材が少なくてストーリーが作れない | Phase 2 の不足洗い出しを飛ばした | 想像で埋めず、質問リストを作ってまとめて聞く |
| 枚数が増え続けて終わらない | 持ち時間から枚数を決めていない | **4-3 で先に枚数を決める。** 作りながら増やさない |
| タイトルもメッセージも主張になっている | タイトルを「事柄の名前」で書いていない | **4-4 の定義へ戻る。** タイトル列だけで目次になるかを見る |
| 上限枚数でも判定を通らない | 枚数の問題ではない | Phase 4 の「通らない場合の戻り先」に従い、4-2／Phase 2／Phase 3 のいずれかへ戻る |
| 相手の情報がほとんどない（初回接触） | 想定のしようがない | **型E**を使う。仮説であることを設計表に明記し、当日の反応で修正する前提にする |
| 「そんなことは分かっている」と言われた | 認識層の判定を誤った（L3の相手にL0の資料） | 1-1 の判定方法で見直す。課題提起を1枚に圧縮し、選択肢と推奨に時間を回す |
| きれいだが相手が動かない | Phase 3 のゴールが「こちらの獲得物」になっていた | 3-4 を読み直し、相手の心理状態で書き直す |
