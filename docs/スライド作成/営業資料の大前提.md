# 営業資料の大前提

🕘 **日付つきの経緯は [`営業資料の大前提_HISTORY.md`](営業資料の大前提_HISTORY.md) にある。** 「なぜ今この状態か」を追うときはそちらを開く。

🔴 **顧客へ持っていく資料を作る前に、必ずこれを読む。** ドクトリン（`ドクトリン.md`）より前に来る、最上位の前提。
初版: 2026-08-24（GoodOld向け説明資料が「何しに来たのか」という資料になっていたため新設）

## 0. 発端

> 本日の結論
> もともと予定している法人向けの販路投資に、最大50万円が乗る制度です。**予定が無いなら、出さないほうが得です。**

指摘：**「こんな資料を営業の場で持ってこられたら、何しに来たのか？と思わないか？」**
続く指摘：**「予定がないなら、予定を作る・提案する。むしろ我々のスキルを活用した販路を提案する。これがあるべき営業ですよね。」**

そのとおりである。この資料は次の状態だった。

- 結論が「**たぶんやめたほうがいい**」で終わっている
- 相手には**5点の宿題**を渡している
- **当社が何を引き受けるのかが、一行も書かれていない**
- **「投資予定がない」という最大の営業機会を、見送りの理由に使っていた**

**調査結果の報告であって、営業資料ではなかった。**

---

## 1. 🔴 大前提 — 営業資料とは何か

> **営業資料とは、相手の事業を前に進めるために、こちらが何を差し出すかを示す文書である。**

したがって次が直ちに従う。

| 従うこと | 意味 |
|---|---|
| **相手に持ち帰りがある** | 相手の時間を使う以上、資料は必ず相手に何かを残す。分析結果を置いていくだけでは、価値提供ではない |
| **こちらが何をするかが書いてある** | 当社が引き受ける範囲が書かれていない資料は、営業資料ではない |
| **前向きな次の一歩で終わる** | 「やめたほうがいい」で終わるのは報告書。営業資料は**行動**で終わる |
| **会う理由がある** | 資料を読めば済む内容なら、送ればよい。訪問するなら、**その場で決まること**を用意する |

---

## 2. 🔴🔴 原則1（最重要）— 「予定がない」は、提案の起点である

**相手に投資予定がないことは、見送りの理由ではない。提案する理由である。**

| ❌ やってしまったこと | ⭕ やるべきこと |
|---|---|
| 「補助対象になる投資予定はありますか」と聞く | **「この販路を作りませんか」と提案を持っていく** |
| 「予定が無いなら見送りましょう」 | **「予定が無いのであれば、一緒に作りましょう。弊社は◯◯を担えます」** |
| 相手の計画の**有無を確認する**資料 | 相手の計画を**こちらから作る**資料 |

**確認しに行くのは調査であって、営業ではない。**

### 提案は、この順序で作る（🔴 順序を逆にしない）

```
① 相手の事業に必要な打ち手は何か   ← 事業から考える
        ↓
② そのうち当社が担える部分はどこか  ← 提供価値を当てる
        ↓
③ そのうち補助対象になる部分はどこか ← 制度は最後
```

⚠️ **②から始めると「売りたいものを売りつける」になり、③から始めると「制度から逆算する」になる。**
どちらも相手の事業を前に進めない（→ CLAUDE.md ビジネス判断の心構え1「制度から逆算しない」）。

**①から始めれば、③は自然に決まる。** 制度は打ち手の資金調達手段にすぎない。

### 当社が提案の材料にできるもの

`スペック/事業計画/事業計画書.md` のサービスラインナップから、相手の事業に効くものを選ぶ。

| 提供価値 | 相手の販路開拓にどう効くか |
|---|---|
| **システム構築・保守** | 受注・在庫・出荷の仕組み化、法人向け受注導線の構築 |
| **コンテンツ制作**（Webサイト・LP・動画） | 法人向けLP、営業資料、商談導線 |
| **AI活用支援** | 問い合わせの一次対応、提案書生成、コンテンツ量産 |
| **IT事業戦略立案** | チャネル別の売上・粗利・継続率を測る仕組みと、その読み方 |
| **CTO派遣** | IT専任者がいない企業のIT全般 |

🔴 **「相手が測れていない数字」は、最も強い提案の入口になる。**
調査で「チャネル別売上・継続率・粗利が不明」と分かったなら、それは**相手も分かっていない**ということであり、
**それを測れるようにすること自体が、当社の売り物になる。**

## 3. 原則2 — 相手に宿題だけを渡さない

**相手に依頼する作業と、当社が引き受ける作業を、必ず同じ資料に並べて書く。**

- ❌ 「5点をご確認ください」だけ
- ⭕ 「5点をご提供いただければ、弊社が要件判定・重複確認・スケジュール逆算まで行い、進め方をご提示します」

依頼だけの資料は、**相手にとって「作業が増えただけの面談」**になる。

## 4. 原則3 — 「やらない」で終わらせない

その打ち手が妥当でない場合でも、**そこで資料を終わらせない。** 必ず次を示す。

- **代わりの打ち手**（別の制度、別の販路、別の順序）
- 条件が変わればいつ再検討するか（**再検討の時期を具体的な日付で置く**）
- この件とは別に、いま着手できること

🔴 **「やめましょう」だけを持っていくなら、訪問する必要がない。** メールで足りる。

## 5. 原則4 — 正直さと後ろ向きさは違う

リスク・負担・不確実性は**必ず正直に書く**（ドクトリン原則3・原則5）。ただし、

- ❌ リスクを書いて「だからやらないほうがいい」で終える
- ⭕ リスクを書いて「**だからこう進める**」「**その部分は弊社が引き受ける**」に着地させる

**リスクの指摘は、実行案の一部として書く。** 単独で置くと、反対意見にしかならない。

## 6. 原則5 — 損得の計算を、相手の代わりに結論づけない

金額の大小だけで「割に合わない」と決めない。相手には、当社の知らない事情がある（関係構築、将来の布石、実績づくり）。

🔴 **見送りを提案する前に、「これで何を実現しようとしているのか」を聞く**（CLAUDE.md ビジネス判断の心構え5）。
資料には**判断材料と推奨**を書き、**決めるのは相手**という形にする。

## 7. 原則6 — 制度・調査の説明で終わらない

制度の内容は、相手も調べられる。**調べれば分かることを説明するだけの資料に、会う価値はない。**

| 項目 | 書くこと |
|---|---|
| **何を提案するか** | 相手の事業を前に進める打ち手 |
| **何を代行するか** | 要件確認、書類作成、制作、スケジュール管理、窓口対応 |
| **何を保証しないか** | 採択、金額、期限に間に合うこと（🔴 誇大にしない） |
| **相手にしかできないこと** | 意思決定、押印、本人認証、事業内容の最終決定 |

## 8. 原則7 — 投資不足の会社に、投資を止める提案をしない

🔴 **当社の顧客も当社自身も、課題は「浪費」ではなく「投資不足」であることが多い**（CLAUDE.md ビジネス判断の心構え2）。

- 「使わなければ得」という比較は、**成長投資の文脈では誤り**
- 補助金の狙いは「単独ではやらない規模の投資を可能にし、**その先のビジネスを生むこと**」
- 資料の姿勢は「**やるなら、こう支える**」であり、「やらないほうが得」ではない

## 10. 同じ事実で、姿勢だけを変える

**事実は1ミリも変えない。順序と主語を変える。**（ドクトリン原則5＝事実を曲げない、と矛盾しない）

| ❌ 報告書の書き方 | ⭕ 営業資料の書き方 |
|---|---|
| 予定が無いなら、出さないほうが得です | **法人販路の立ち上げをご提案します。この投資に最大50万円の補助を充てられます** |
| 補助対象になる投資予定はありますか | **こういう販路が作れます。まず何から着手するかを決めましょう** |
| 事務が重いのは採択された後です | 採択後の事務は相応の負担が生じます。**この部分を弊社が引き受けます** |
| 入口は2つ。どちらも御社しか答えられません | 入口は2つです。**判定に必要な確認は弊社が行います**ので、資料のご提供をお願いします |
| 9月中に進むか止めるかが決まります | 9月中に方針を確定し、**12月の申請に間に合わせます** |
| 50万円のために新しい仕事を作るなら推奨しません | **もともと必要な投資に充てるのが最も効果的です** |

⚠️ **これは「都合よく編集する」ことではない。** 不利な事実（後払い・事務負担・重複リスク）は**すべて残したまま**、
「だから当社がこう支える」「だからこの順で進める」という**実行の文脈**に置き直している。

## 11. 訪問前の自己点検（🔴 これに答えられないなら行かない）

- [ ] 🔴 **こちらから提案する打ち手があるか**（相手の予定を確認しに行くだけになっていないか）
- [ ] 🔴 **その打ち手のうち、当社が担う部分が書いてあるか**
- [ ] 🔴 **作るものを、現物（見本・画面・帳票）で見せているか**（言葉と箱の図で済ませていないか → 原則8）
- [ ] 🔴 **その現物のうち、買う側が触るものを最初に見せているか**（管理画面から始めていないか → 原則8）
- [ ] 提案を**事業 → 当社の役割 → 制度**の順で組み立てたか（制度や自社商品から逆算していないか）
- [ ] **この面談で、相手に何が残るか**を1文で言えるか
- [ ] 相手への依頼と、当社の作業が**同じ資料に並んでいる**か
- [ ] 結論が**行動**で終わっているか（「やめたほうがいい」で終わっていないか）
- [ ] 見送りを提案する場合、**代わりの打ち手か再検討時期**を書いたか
- [ ] 相手の事業を**前に進める**姿勢になっているか（止める姿勢になっていないか）
- [ ] この内容は、**送るのではなく会って話す必要があるか**

## 12. 例外 — 報告書として作ってよい場合

| 場面 | 理由 |
|---|---|
| 相手から**調査そのものを受注**している | 成果物が調査結果であり、判断は相手が行う |
| 社内向けの検討資料 | 営業ではない |
| 相手が明確に「調べた結果だけ欲しい」と言っている | 依頼の範囲を超えない |

⚠️ ただし、その場合でも**「次に何をするか」の選択肢は示す**（ドクトリンのアンチパターン「ご検討ください で終わる」）。

## 9. 🔴 原則8 — 作るものは、言葉で書かず、現物を見せる（2026/8/27 追加）

**発端**: GoodOld向け提案の第4版に対する指摘。

> **「今の提案資料は、具体性がない。ソリューションサンプルを作っているので、具体的にはこんなイメージのソリューションを作ることでお役に立つ、という内容を加味して」**

資料には、作るものがこう書いてあった。

> 法人向けの案内ページ／取引条件シート／お見積り／引き合いの一覧／経路ごとの売上と利益

**この5語は、作る側にとっては十分だが、受け取る側には何も見えていない。**

| 起きること | |
|---|---|
| 相手は、届くものを**思い浮かべられない** | ↓ |
| 思い浮かべられないので、**要否も金額も判断できない** | ↓ |
| 判断できないので、面談は「**検討します**」で終わる |

🔴 **最も痛かったのは、見本がすでに手元にあったことである。** 3日前に作った見本5点が別フォルダにあり、資料には1枚も入っていなかった。
入っていたのは、**その見本を言葉と箱に戻した構造図**だった。

### 従うこと

| | |
|---|---|
| **現物があるなら、現物を出す** | 見本・試作・画面・帳票が手元にあって、それが資料に入っていない状態を「完成」と呼ばない |
| **無いなら、作ってから行く** | 「言葉で説明して、決まったら作る」の順序にしない。**決めるために現物が要る** |
| **相手が決める箇所は、空欄のまま見せる** | 🔴 **空欄の入った完成形は、「これを決めてください」という依頼より速い。** 数値を入れて出すと、こちらが勝手に決めた案になる |
| **見本だと必ず先に言う** | 会社名・数値・日付が仮置きであることを、**口頭でも資料上でも**明示する。実在と誤認されると、存在しない条件が独り歩きする |
| **図で代用しない** | 箱と矢印の構造図は、**現物が無いときの代替**である。現物があるのに図を出すのは、情報を減らしているだけ |

### 🔴 誰が触る画面かで、見せる順番が決まる（2026/8/29 追加）

**発端**: 同じGoodOld向け提案の次の版で、こう指摘された。

> **「クライアントが触る管理ページを載せていますが、一番のメインはエンドユーザーが触る購入ページがメインのはずです、ここのクオリティがすべてを左右する」**

現物を載せるところまでは直した。**ところが、載せた現物の主役が逆だった。**

| 資料に載せていた画面 | 誰が触るか |
|---|---|
| 引き合いの一覧 | **顧客の社内**（管理） |
| 経路ごとの売上と利益 | **顧客の社内**（管理） |
| — | 🔴 **買う側が触る画面は1枚も無かった** |

🔴 **売上が立つのは、買う側が画面を見て「これなら買える」と判断する瞬間である。**
管理画面は、その後の話でしかない。

| 従うこと | |
|---|---|
| **買う側の画面を最初に、最も大きく見せる** | 相手の顧客が触るものが主役。顧客の社内で使う画面は Appendix へ |
| **買う側の判断材料を、その画面に置く** | 🔴 相手の顧客が最も知りたいことは何か。物販なら「**いくらで仕入れて、いくら残るか**」。ここが無い画面は、きれいでも判断に使えない |
| **導線そのものを設計する** | 「問い合わせ → 見積 → 申込」は、**紙の商流をWebに置き換えただけ**になりやすい。待たせる工程が要るのかを疑う |
| **管理画面は「その後どうなるか」として添える** | 先に出すと、相手の事業ではなく相手の事務の話になる |

⚠️ **順番を間違えると、良い現物を作っていても提案は伝わらない。** 見せる順番は、設計の一部である。

### ⚠️ 図が要る場合

**現物どうしの関係**（何がどこから出るのか）は、現物を並べても伝わらない。ここだけは図が要る。
→ **図は Appendix に置き、本編は現物で埋める。**

### 版面に載らない、という言い訳をしない

A4の帳票や縦長の画面は、16:9のスライドにそのままでは載らない。**載らないのは事実だが、それは出さない理由にならない。**

- **横長の帯として使える部分を切り出す**（一覧、条件表、KPIの行、手順の帯）
- 全景は Appendix へ回し、**本編では読ませずに「形」を見せる**
- 🔴 **A4の見本は、印刷して手渡すのが最も強い。** その場合も資料には縮小を載せ、**話の流れから外さない**
