## ⚠️ CSS が無いと、検査は「0件」で通ってしまう（2026/8/30 追記）

**本スクリプトは、対象HTMLと同じフォルダの `css/` を作業フォルダへコピーする。**
`css/` が同階層に無いと、**CSSが当たらない状態で描画され、はみ出しは原理的に検出できない。**
このとき `fit` は堂々と「0件」を返す。

🔴 **実害が出ている。** `テンプレート/samples/` に `css/` が無いため、
`sample_deck.html` への `fit` はずっとCSS無しで通っていた。
その結果、`.big-num` が**常に約21pxはみ出す**というテンプレート側の不具合が、2026/8/25 の総点検をすり抜けた。

**したがって、`fit` を実行したら次を確認する。**

- [ ] 対象HTMLと同じフォルダに `css/` がある（作業フォルダの `css/` にファイルがコピーされている）
- [ ] 「0件」が出たとき、**②の画像が実際にスタイルどおりに描画されているか**を1枚は目で見る

## ⚠️ `fit` では原理的に出ないもの（2026/8/31 追記）

**箱からはみ出していないので、`fit` は 0件を返す。しかし読みにくい。**

| 症状 | 例（2026/8/31） | 見つけ方 |
|---|---|---|
| 🔴 **泣き別れ**（単語が行末で割れる） | 「案件の中に入り込み、チ／ーム全体が…」 | **転記者の目視のみ。** 対処は `<span class="nb">` で分割禁止。⚠️ **2026/9/12 まで `.nb` は効いていなかった**（`word-break: keep-all` の不足。`../テンプレート/README.md` の CSS 修正履歴）。それ以前の資料では、nb を書いても割れている |
| 強調帯が枠の罫線まで到達 | 6枚目のメッセージライン | 同上。`<em>` の範囲を変えて折り返し位置をずらす |

🔴 **したがって、転記を依頼するときは「単語が行末で不自然に割れているページ」も報告させる。**

⚠️ **「0件」は、崩れていないことの証明ではなく、検出できなかったことの報告でもある。**

### 🔴 SVGの中身は「箱のはみ出し」判定から外している（2026/8/25）

`fit` の最後に、次の行が必ず出る。

```
--- SVG内 44件を箱の判定から除外（Chromeが位置の値を返すため。README参照）---
  うち 1件は、除外しなければ報告されていました:
    p06_7	text	w+24 h+7	（日）
```

#### なぜ外すか — Chromeが返す値がはみ出し量ではない

Chrome は **SVGの子要素**の `scrollWidth` / `clientWidth` / `scrollHeight` / `clientHeight` に、
はみ出し量ではなく**位置・寸法の値**を返す。しかも単位系が揃っていない。

`sample_deck.html` の T-07 グラフでの実測値:

| 要素 | `scrollWidth` | `clientWidth` | 差 | 結果 |
|---|---:|---:|---:|---|
| `<text x="58" text-anchor="end">7.0</text>` | 58 | 58 | 0 | 偶然一致し、無風 |
| `<text x="20">（日）</text>` | 86 | 62 | **24** | **誤検出** |

差はビューボックスの拡大率と `x` / `y` 属性に連動しており、**はみ出しとは無関係**である。
つまり **SVGの子要素では、この差がいくつであっても意味がない。** だから判定しない。

#### 何を外し、何を残したか

| 対象 | 箱のはみ出し（CLIP/SPILL） | OUT |
|---|---|---|
| HTML要素 | **判定する**（従来どおり） | 判定する |
| **`<svg>` 自身** | **判定する。** SVGが親の箱からあふれるのは本物の不具合 | 判定する |
| `<svg>` の中の要素（`text` `rect` `g` 等） | 🔴 **判定しない** | ✅ **判定する** |

**`OUT` をSVGの中身にも残した理由**: `OUT` は `getBoundingClientRect()`（実際の描画位置）で見ており、
**SVGの中の要素でも値が正しい**。実測で、スライドの枠外へ出した `<text>` は正しく `OUT` になり、
枠内の `<text>` は反応しないことを確認している。**SVGの図の一部が版面から出る**のは実際に起きるため、残す価値がある。

#### ⚠️ この修正で見えなくなるもの

**SVGの内部だけで完結する崩れは、機械では出なくなった。** 例:

- SVG内のテキストどうしが重なっている
- 図形の外へ文字がはみ出している（ただし版面の外まで出れば `OUT` で出る）
- ラベルが図形に対して長すぎる

→ 🔴 **SVGを使ったページは、②の画像で必ず目視すること。** もともと `fit` は重なりを検出できないが、
SVGについては**はみ出しも見なくなった**ため、目視の比重が上がっている。

⚠️ **除外した件数と中身は必ず表示している。** 黙って捨てると、本物の不具合まで見えなくなるため。
表示された「除外しなければ報告されていました」の行は、**偽陽性と判断したもの**である。
納得できない場合は、そのページの画像を開いて確認すること。

#### ⚠️ 実装上の落とし穴（同じ間違いをしないため）

除外の判定に **`el.ownerSVGElement !== null` を使ってはいけない。**

HTML要素では `ownerSVGElement` が `undefined` のため、この式は **`true` になる**。
これで除外すると **HTML要素まで全部除外され、検査そのものが無音で無効になる**（実測で確認済み）。

```js
// ❌ HTML要素も全部除外されてしまう
var inSvg = el.ownerSVGElement !== null;

// ✅ <svg> 自身は残し、その中身だけを外す
var inSvg = (el instanceof SVGElement) && !(el instanceof SVGSVGElement);
```

### 🔴 出力の文字コード（2026/8/25）

**Windows の既定コンソールは cp932 で、`⚠` `🔴` を encode できずに落ちる。**
検出結果を出したあとで `UnicodeEncodeError` になるため、**「最後まで走ったのか、途中で死んだのか」が分からなくなる。**
→ スクリプト冒頭で `sys.stdout` / `sys.stderr` を UTF-8 へ強制している。**この処理を消さない。**

### 🔴 絵文字の異体字セレクタで、偽の不一致が出ていた（2026/8/25）

**「⚠️」は `⚠`(U+26A0) + **U+FE0F**（異体字セレクタ）の2文字**である。
画像から書き起こすと U+FE0F は付かないため、そのままでは必ず不一致になる。しかも厄介なことに、
**「⚠」の手前までは一致するため、`[途中で切れている]` として「⚠以降が欠落」という偽の報告が出る。**

```
[途中で切れている] p14_A5
    表示: 「…全額が貴社のご負担になります。⚠」
    欠落: 「️弊社の補助金支援費は補助対象外のため…」   ← 先頭に見えない U+FE0F がある
```

→ `norm()` で U+FE0F / U+FE0E を落とすようにした。あわせて `—` `ー` `･` `▪` `●` の記号ゆれも吸収する。
**実測で 13件 → 7件**（6件が偽陽性だった）。

⚠️ **絵文字を資料に使う限り、この手の差は出続ける。** 不一致を見たら、**まず「見えない文字の差ではないか」を疑う。**

## 🔴 画像を使う資料では、資産を手で複製する（2026/8/27 判明）

**`fit` も `shots` も、作業ディレクトリへ複製するのは `css/` フォルダだけである。**
`<img src="...">` で画像を読み込んでいる資料では、**画像が読み込まれないまま検査が走る。**

| | 起きること |
|---|---|
| 症状 | 画像の代わりに `alt` テキストが1行だけ表示される。**版面の高さが実物と全く違う**まま「① 0件」と出る |
| 見つけ方 | 🔴 **②の画像を目視すれば一目で分かる。** ①の結果だけを見ていると気づけない |
| 回避 | 検査の前に、**HTMLが参照している画像フォルダを作業ディレクトリの同じ相対パスへ複製する** |

```bash
WORK="<スクラッチパッド>/hyoji"
mkdir -p "$WORK/<画像フォルダの相対パス>"
cp -r "<画像フォルダ>" "$WORK/<その親の相対パス>/"
python "$SCRIPT" fit   スライド.html "$WORK"
python "$SCRIPT" shots スライド.html "$WORK"
```

⚠️ **`fit` の「0件」を、画像が載った状態の0件と読み替えてはいけない。**
画像を使う資料では、**画像が写っていることを②の1枚目で確認してから**①の結果を採る。

### 対処案（未実施）

複製対象を `css/` 固定ではなく、**HTMLが参照している相対パスの資産すべて**（`<img src>`・`<link href>`・`url()`）へ広げる。
実例: `プロジェクト/_完了/20260824_GoodOld補助金調査/提案_GoodOld_20260824/09_第5版_改訂記録_20260827.md` 6項。
