## なぜあるか

2026年8月25日、納品直前の資料で**文字が隠れている箇所**が見つかった。直前の検査では「オーバーフロー0件」と報告していた。**2回続けて外した。**

### 外した原因1 — `<section>` 単位でしか見ていなかった

子要素の中で文字が溢れても、**親の `<section>` の `scrollHeight` は変わらない**。

### 🔴 外した原因2 — `overflow: hidden` の要素しか調べていなかった

`scrollHeight > clientHeight` は **`overflow` の値に関係なく**「中身が箱に収まっていない」を意味する。
帯（`.road-bar`）は `overflow: visible` なので、条件から漏れていた。

| overflow | はみ出したときに起きること | 報告名 |
|---|---|---|
| `hidden` / `clip` | **文字が切れる** | `CLIP` |
| `visible`（既定） | **箱の外へあふれ、隣と重なる** | `SPILL` |

→ **両方とも不具合。`overflow` の値で絞り込まない。**

## 🔴 順序を守る

**認識する側が、期待テキストを知らない状態で読む。**

画像を読むのは私（モデル）である。**そのとき `expected.json` を持っていると、書いてあるはずの文字を読んでしまう**（切れていても補完する）。そうなると突合は原理的に不一致を出せず、**自分の期待と自分の期待を突き合わせているだけ**になる。

```
shots（画像化） → 転記（私が読む） → expect（期待値） → diff（突合）
                        ↑                   ↑
                  期待値を開かない    転記が終わってから出す
```

## `hyoji_check.py`

| コマンド | 順 | すること |
|---|---|---|
| `fit` | ① | **全要素**の箱のはみ出しを検出（`CLIP` / `SPILL` / `OUT`） |
| `shots` | ② | **1スライド1枚**の PNG（1280×720）を書き出す |
| （人手） | ③ | 画像を1枚ずつ開き、**見えたとおりに** `seen/<同名>.txt` へ転記 |
| `expect` | ④ | DOM から**期待テキスト**を抽出（🔴 ③の後に実行。未転記があると警告する） |
| `diff` | ⑤ | ③と④を突合し、**欠落・途中で切れている箇所**を出力 |

### 使い方

```bash
cd <スライドHTMLのあるフォルダ>
SCRIPT="C:/VS/estelaworks/スペック/システム/スライド作成/検査スクリプト/hyoji_check.py"
WORK="<スクラッチパッド>/hyoji"      # 🔴 必ず ASCII のパス

python "$SCRIPT" fit    スライド.html "$WORK"
python "$SCRIPT" shots  スライド.html "$WORK"
#   ③ 画像を Read で1枚ずつ開き、seen/<同名>.txt へ転記
python "$SCRIPT" expect スライド.html "$WORK"
python "$SCRIPT" diff   "$WORK"
```

### `fit` の出力

```
ページ	種別	要素	はみ出し量	中身（先頭24字）
p06_6	SPILL	road-bar	w+0 h+21	業種のご決定、取引条件の整理、要件判定
```

| 種別 | 意味 |
|---|---|
| `CLIP` | `overflow: hidden/clip` の箱からはみ出し → **文字が切れる** |
| `SPILL` | `overflow: visible` の箱からはみ出し → **あふれて隣と重なる** |
| `OUT` | 要素がスライドの枠から出ている |

### `diff` の出力

| 出力 | 意味 | 主な原因 |
|---|---|---|
| `[途中で切れている]` | 先頭は見えるが途中から画像に無い | 🔴 **枠で切れている** |
| `[まるごと見えない]` | 画像に一切無い | 枠外／重なりで隠れている／文字色が背景と同色 |
| `[未転記]` | ③をやっていないページがある | **見ていないページを残さない** |

---

### 🔴 終了コードで合否を判定しない

`main()` が戻り値を返さないため、**検出が何件あっても終了コードは 0 になる。**
→ 最後の1行で必ず合否を言い切るようにした。

| 出力の最終行 | 意味 |
|---|---|
| `🔴 ① は未通過です（N件）。` | **直して ① からやり直す** |
| `① 0件。⚠️ ただし重なり・改行崩れ・可読性は出ません。` | ② へ進んでよい |

⚠️ **`exit 0` を「0件」と読み替えない。** 最終行を読むこと。

## 注意

- 🔴 **`WORK` は ASCII のパスにする。** 日本語パスは `file:///` のエンコードで詰まる（スクリプトが検出して止める）
- `css/` はスクリプトが自動でコピーする
- ⚠️ **`diff` の出力を鵜呑みにしない。** ③は人手なので転記ミスで偽の不一致が出る。**直す前に画像をもう一度開いて確認する**
- 🔴 **直したら ② からやり直す。** 1か所の短縮が、他ページの折り返しを変えることがある
- 🔴 **短くする修正は文言の変更である。** 直した箇所へ Phase 8-2 の検査語を当て直す
- 🔴 **SVGを使ったページは、`fit` が0件でも必ず画像で目視する。** SVGの内部の崩れは機械では出ない（→ 上記「SVGの中身は…」）

## 突合では出ないもの（不一致0件になってから、一度だけ通し見る）

機械の突合は「文字があるか」しか見ない。

- 文字どうしの**重なり**（重なっても両方読めれば突合は通る）
- 改行位置の不自然さ（1語だけ折り返す、助詞で切れる）
- 空白の不自然さ（下半分が空、1行だけの段）
- **投影時の可読性**（最小の文字が読めるか）
- 色・罫線がモノクロ印刷で判別できるか

⚠️ **これを判定の主役にしない。** 主役は `fit` と `diff` の機械検出である。
