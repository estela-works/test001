## 全体像

```
[素材受領] ─┐
            ├─> ① 相手を想定する（認識層・感情・懸念・意思決定構造・環境）
            └─> ② 事実を整理する（事実／分析／主張 の三層 ＋ 出典・確度）
                          │
                          v
                 ③ ゴール認識を定義する（相手のAfter心理状態）  🔴 本人確定
                          │
                          v
                 ④ ストーリー（枚数を先に決める）
                    🔴 全スライドの**タイトル**（事柄の名前）と
                       **メッセージ**（主張）を固める
                          │ ゲート1（目次）・ゲート2（話）・判定4項目
                          v
                 ⑤ 設計（枚数と見出しはここで変えない）
                    🔴 各スライドの**コンテンツ**（何が載るか）と
                       **テンプレート**（T-01〜T-16）を決める
                          │
                    🔴 本人レビュー・承認（作り込む前に設計で合意）
                          v
                 ⑦ 制作
                          v
                 ⑧ 品質チェック
                          v
                 ⑧-2 🔴 言葉遣いの最終見直し（内容を凍結してから、言葉だけを見る）
                          v
                 ⑧-3 🔴 表示確認（1ページ＝1画像に書き出し、全ページを目で見る）
                          v
                 ⑨ 納品・記録
                                                  │
                          テンプレ・ドクトリンへ還元 ◀┘（学習ループ）
```

**設計上の要点は3つ。**

1. 🔴 **④と⑤を分ける。** ④で**タイトルとメッセージ**だけを固め、⑤で**コンテンツとテンプレート**を決める。
   ④で図表を考え始めると、**言いたいことより描けるものに引っ張られる**。
   枚数は**持ち時間から先に決める**（上限18枚）。作りながら増やさない
2. **レビューゲートは⑤に置く。** 作り込んでからの構成変更が最大の手戻り
3. **⑨で還元する。** 商談後の反応をテンプレートとドクトリンに戻す。ここがないと3本目以降が速くならない
4. 🔴 **⑧-2を独立させる。** 言葉遣いは、内容を考えながらでは直せない。**内容を凍結したうえで、言葉だけを見るパスを最後にもう1回通す**（2026/8/24 追加）
5. 🔴 **⑧-3で必ず目で見る。** DOMの数値が0でも、内側の要素で文字が切れていることがある。**1ページずつ画像にして見るまで、崩れていないと判断しない**（2026/8/25 追加）

## Phase 7 — 制作

**手順の詳細は `テンプレート/README.md`。** ここでは要点だけ。

1. 設計表の各行について `テンプレート/templates/TXX_*.html` をコピーし、作業フォルダへ置く
2. `〈  〉` のプレースホルダを置き換える。**行を減らすのは可、増やすのは各テンプレートに書かれた上限まで**
3. 16枚を1ファイルにまとめる（`テンプレート/samples/sample_deck.html` の構造をそのまま使う）
4. **図はここで初めて作る**（構成が固まる前に作図しない）。グラフは SVG を `viewBox="0 0 660 330"` で手書きし、色は緑（強調）と灰（地）の2色に抑える
5. **スピーカーノートを書く** — `<div class="notes">…</div>` に置く。**画面では見え、印刷では自動で消える**
6. PDF化: Chrome で `Ctrl+P` →「PDFに保存」／**余白: なし ／ 背景のグラフィック: ON**（忘れると色面が全部消える）／倍率: 既定

**一括出力**

```
"C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu ^
  --no-pdf-header-footer --print-to-pdf="出力先.pdf" "file:///対象.html"
```

⚠️ **共通規約C1〜C12と情報量の上限**（`テンプレート/README.md`）を守る。検査は Phase 8。

## Phase 8 — 品質チェック

**→ `品質チェックリスト.md` を参照。**

---

#   ③ 画像を Read で1枚ずつ開き、seen/<同名>.txt へ「見えたとおりに」書き出す
python "$SCRIPT" expect スライド.html "$WORK"   # ④ 期待値（🔴 ③の後に実行）
python "$SCRIPT" diff   "$WORK"                 # ⑤ 突合
```

⚠️ 作業フォルダは **ASCIIのパス**にする。日本語パスは `file:///` のエンコードで詰まる（スクリプトが検出して止める）。
⚠️ `css/` はスクリプトが自動でコピーする。

### ③ 転記の書き方（🔴 ここだけが人手）

- **見えたとおりに書く。** 途中で切れていたら、**切れたところまでを書く**（勝手に補完しない）
- 重なり・小ささで判別できない箇所は `[判読不能]` と書く
- 画像に見えない文字は**書かない**
- ファイル名は `expected.json` のキーと同じにする（`p03_3.txt` など）
- 🔴 **転記が全ページ終わるまで、④を実行しない**

### ⑤ 出力の読み方

| 出力 | 意味 | 主な原因 |
|---|---|---|
| `[途中で切れている]` | 期待テキストの先頭は見えるが途中から画像に無い | 🔴 **枠で切れている**（帯・カード・セル） |
| `[まるごと見えない]` | 期待テキストが画像に一切無い | 枠外／重なりで隠れている／文字色が背景と同色 |
| `[未転記]` | ③をやっていないページがある | **見ていないページを残さない** |

⚠️ **不一致が出たら、そのページの画像をもう一度開いて確認してから直す。**
③は人手なので、**転記ミスで偽の不一致が出る**。機械の出力を鵜呑みにしない。

### ⑦ 直し方

| 症状 | 原因 | 直し方 |
|---|---|---|
| 帯（`road-bar`）の中の文字が切れる・あふれる | 文字量に対して帯の幅が狭い | 🔴 **文言を短くする。** 幅を広げると日程の意味が変わる |
| カード（`role-tasks`）の文が途中で消える | 1枚に詰め込みすぎ | 要素を3つまでに絞る／文を短くする |
| 表のセルで文字が切れる・重なる | 列が多い、1セルが長い | 列を減らす／その行をAppendixへ回す |
| 見出しが3行になる | タイトルが50字超 | 規約C2に従い45〜50字へ |
| 下端が切れる | 軽量版で行数超過 | 軽量版の上限（箇条書き3・表4行）へ戻す |
| 出典行が2行を超える | 出典が長い | 出典を統合する／確認日を末尾にまとめる |

🔴 **直したら ② へ戻る。** 直した箇所だけでなく、**全ページを取り直して転記し直す**（1か所の短縮が他ページの折り返しを変えることがある）。
🔴 **短くする修正は文言の変更である。** 直した箇所へ **Phase 8-2 の検査語を当て直す。**

### 突合では出ないもの（不一致0件になってから、一度だけ通し見る）

機械の突合は「文字があるか」しか見ない。

- [ ] 文字どうしが**重なっていない**（重なっても両方読めれば突合は通る）
- [ ] 改行位置が不自然でない（1語だけ折り返す、助詞で切れる）
- [ ] 空白が不自然でない（下半分が空、1行だけの段）
- [ ] **投影を想定して、最小の文字が読めるか**
- [ ] 色・罫線がモノクロ印刷で判別できるか

⚠️ **これを判定の主役にしない。** 目視は最後の1回だけ。主役は①と⑤の機械検出である。

### ゲート

- [ ] ① の `CLIP` / `SPILL` が **0件**
- [ ] ② で **全ページ**の画像を出した
- [ ] ③ で **全ページ**を転記した（`[未転記]` が出ない）
- [ ] 🔴 ③ が終わってから ④ を実行した
- [ ] ⑤ の不一致が **0件**
- [ ] 上記「突合では出ないもの」を画像で確認した
- [ ] PDFのページ数が想定どおり
- [ ] 直した箇所に Phase 8-2 の検査語を当て直した

🔴 **画像を出さずに「崩れていない」と報告しない。** 2026/8/25 の指摘は、まさにそれを2回やって出た。

## Phase 8-2 — 🔴 言葉遣いの最終見直し（2026/8/24 追加）

**内容が確定したあとに、言葉遣いだけを見るパスを、独立してもう1回通す。**

### なぜ独立させるか

2026年8月24日、顧客向け資料で口語表現の指摘を受けた（「取りに行く」「出さないほうが得です」「50万円が乗る」）。
規範（`ビジネス文書作法/文体規範.md`）を新設したうえで作り直したが、**次の版では別の身内の言葉が入り込んだ**（「提案して入る販路」「業態」「商談導線」「採算を測る仕組み」）。

原因は、**内容を考えながら言葉も見ようとしたこと**である。構成・事実・懸念を組み立てている最中は、言葉は「意味が通れば足りる」状態で書かれる。
🔴 **したがって、内容を凍結してから、言葉だけを見る工程を分ける。**

### 手順

1. **内容を凍結する。** ここで構成・事実・枚数を変えない。変えたくなったら Phase 4〜5 へ戻り、8-2 をやり直す
2. **機械検査を通す**（下記）。スピーカーノートは口語でよいため、**必ずノートを除外して本文だけを検査する**
3. **通しで音読する。** 機械検査に掛からない不自然さ（主語が不明、係り受けの崩れ、身内の言葉）はここでしか見つからない
4. 🔴 **「その語を、相手は使うか」で判定する。** 社内の議論で使っていた略語は、そのまま資料へ載せない（→ §言い換えの原則）
5. **`品質チェックリスト.md` E-0 を埋める。** 機械検査の件数を結果ファイルに残す
6. **見つかった誤りは規範側へ還元する**（`ビジネス文書作法/04_言い換え辞書.md` と `指摘ログ.md`）。**資料だけ直して終わりにしない**

### 機械検査（本文のみ・ノート除外）

```bash
python - << 'EOF'
import re, html
s = open('スライド.html', encoding='utf-8').read()
s = re.sub(r'<!--.*?-->', '', s, flags=re.S)
body = re.sub(r'<div class="notes">.*?</div>
', '', s, flags=re.S)   # ノートを除外
txt = html.unescape(re.sub(r'<[^>]+>', '', body))
NG = ['御社','御社様','貴社様','当社','取りに行','得です','お得','乗る','2/3',
      '必ず','絶対','確実','？','！','なので','だから','でも','けど','ちょっと',
      'やっぱり','してる','してます','させていただ','ヶ月','逃す','みたいな']
for w in NG:
    n = txt.count(w)
    if n: print(f'{w}: {n}')
print('--- 検査終了 ---')
EOF
```

⚠️ `当社` は**社外向けの営業資料では「弊社」**（中立文書は「当社」でよい）。`2/3` は `3分の2`。

### 言い換えの原則（機械検査に掛からないもの）

| 判定 | 内容 |
|---|---|
| 🔴 **身内の言葉** | 社内の議論で使っていた略語をそのまま載せない（例: 商談導線 → 問い合わせを受ける窓口／採算 → 売上と利益） |
| 🔴 **主語** | 「◯◯します」の主語が貴社か弊社か、文だけで分かるか。分からなければ文を割る |
| **専門用語・外来語** | 言い換えるか、1行の説明を付ける（公用文Ⅲ／`06_表記ルール` 5-2・5-3） |
| **確度** | 「採択されます」と書いていないか。「採択された場合」「見込まれます」になっているか |
| **相手の状態** | 否定形で名指ししていないか（「まだ取れていない」→「未開拓の」、または表現ごと削除） |
| **損得・比喩・煽り** | `文体規範.md` §4 |

## Phase 8-3 — 🔴 表示確認（画像とテキストの突合）2026/8/25 追加

**スライドを1枚ずつ画像に出し、画像から文章を認識し、HTMLの期待テキストと機械で突合して、一致しない箇所を特定する。**

スクリプト: `検査スクリプト/hyoji_check.py`（使い方は `検査スクリプト/README.md`）

---

### なぜ必要か

2026年8月25日、納品直前の資料で**文字が隠れている箇所**が見つかった。直前の検査では「オーバーフロー0件」と報告していた。**2回続けて外した。**

#### 外した原因1 — `<section>` 単位でしか見ていなかった

| 見落とす類型 | なぜ数値に出ないか |
|---|---|
| **内側の要素で切れている** | 子要素の中で溢れても、**親の section の `scrollHeight` は変わらない** |
| **幅の決まった要素で切れている** | 帯・カード・表のセルなど、箱の中で文字が切れても外側の高さは変わらない |
| **要素どうしの重なり** | 重なっても `scrollHeight` は増えない |
| **改行位置の崩れ・可読性** | そもそもDOMから分からない |

#### 🔴 外した原因2 — `overflow: hidden` の要素しか調べていなかった

```js
var hid = (overflowX が hidden/clip) || (overflowY が hidden/clip);
if (hid && はみ出し) → 報告        // ← ここが誤り
```

**`scrollHeight > clientHeight` は `overflow` の値に関係なく「中身が箱に収まっていない」を意味する。**
帯（`.road-bar`）は `overflow: visible` なので、中身がはみ出しても上の条件に入らず、**検出できなかった**。

| overflow の値 | はみ出したときに起きること | 報告名 |
|---|---|---|
| `hidden` / `clip` | **文字が切れる** | `CLIP` |
| `visible`（既定） | **箱の外へあふれ、隣と重なる／枠から出る** | `SPILL` |

→ **両方とも不具合である。`overflow` の値で絞り込まない。**

### 🔴 ③ の転記は、原稿を知らない相手にやらせる（2026/8/25 改良）

**本工程で最も重要な決まり。** これまでは「期待値を後から出す」という**順序**で循環を避けていた。
しかし**自分（および文脈を引き継いだサブエージェント）は原稿を知っている**。知っている以上、
切れた文字を無意識に補完する余地が残る。

→ **転記は、この資料の文脈を一切持たないサブエージェントに任せる**（`Agent` ツールで `subagent_type` に
`fork` **を使わない**。fork は文脈を引き継ぐため意味がない）。渡すのは**画像フォルダのパスだけ**とし、
`スライド.html`・`.md`・`expected.json` を開かないことを明示する。

⚠️ **順序の工夫より、こちらのほうが強い。** 原稿を知らなければ、補完のしようがない。

**副産物**: 原稿を知らない読み手は、**改行の不自然さに気づきやすい**。
2026/8/25 の実行では、機械では出ない次を報告してきた——「ん」1文字だけの行、「の」1文字だけの行、
見出し2行目が「す」1文字、脚注の行頭が助詞から始まる。**これは③の副産物として期待してよい。**

### 🔴 設計の要（順序を守る）

**認識する側が、期待テキストを知らない状態で読む。**

私（モデル）が画像を読む。**そのとき `expected.json` を持っていると、書いてあるはずの文字を読んでしまう**（切れていても脳内で補完する）。そうなると突合は原理的に不一致を出せず、**自分の期待と自分の期待を突き合わせているだけ**になる。

```
② 画像化  →  ③ 転記（私が読む）  →  ④ 期待値の抽出  →  ⑤ 突合
                    ↑                      ↑
              ここでは期待値を         転記が終わってから
                 開かない                 初めて出す
```

⚠️ **④を③より先にやらない。** これが本工程で最も重要な決まりである。
