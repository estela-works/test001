## 使い方

1. `../ワークシート雛形/05_設計表.md` の各行について、**その行が答える問い（Q1〜Q8）**から `index.html` で型を選ぶ
   - ⚠️ **Q1〜Q8 は「型A 問題提起型」の連鎖。** 型B〜Eで作った場合は `../内容検討ガイド.md` 4-1「型ごとのテンプレート対応」で引く
2. 該当する `templates/TXX_*.html` をコピーし、作業フォルダ（`プロジェクト/<案件>/提案_<相手先>_<日付>/`）に置く
3. `〈  〉` を置き換える。**行を減らすのは可、増やすのは各テンプレートに書かれた上限まで**
4. 16枚を1ファイルにまとめる（`samples/sample_deck.html` の構造をそのまま使う）
5. `../品質チェックリスト.md` で検査 → PDF化

### 🔴 どちらを既定にするか

| 相手 | 既定 |
|---|---|
| **中小企業の経営者** | 🔴 **軽量版**（決定④の主戦場） |
| 大企業のIT部門・稟議資料 | 標準版 |
| 迷ったら | **軽量版**。足りなければ標準へ戻すのは容易だが、逆は相手の時間を奪った後になる |

### 中小企業の経営者向けにするとき（軽量バリアント）

`<section class="slide">` を **`<section class="slide slide--lite">`** にする。それだけで

- 本文が 21px → 23px に上がる
- `class="lite-hide"` の付いた要素（4件目以降・5列目以降）が消える
- 出典が脚注扱いに落ちる

**HTMLの作り直しは不要。** 減らしてよい要素にはテンプレート側で `lite-hide` を仕込んである。

## PDF化の手順

**Chrome で `Ctrl+P` →「PDFに保存」**

| 設定 | 値 |
|---|---|
| 送信先 | PDFに保存 |
| 余白 | **なし** |
| 背景のグラフィック | **ON**（これを忘れると色面が全部消える） |
| 倍率 | 既定 |

1スライド＝1ページで出力される。**用紙は 960×540pt（＝13.333in × 7.5in）で、PowerPoint 既定の16:9と完全に一致する。**
スピーカーノートは印刷時に自動で消える（画面でのみ表示）。

**コマンドで一括出力する場合**

```
"C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu ^
  --no-pdf-header-footer --print-to-pdf="出力先.pdf" "file:///対象.html"
```

## 書体について

**和文 `BIZ UDPGothic` ／ 欧文 `Segoe UI`。外部フォントの読み込みは行っていない。**

- HPの `UD新ゴ` は**さくらWebフォント（CDN配信・契約ドメイン限定）**のため、ローカルHTMLやPDF埋め込みには使えない
- `BIZ UDPGothic` は同じモリサワのユニバーサルデザイン書体で、**Windows に同梱**され、**SIL OFL** で配布されている
- PDF化するとChromeが自動でサブセットを埋め込むため、**フォントが入っていないPCでも表示は崩れない**
- ウェイトは Regular / Bold の2段のみ。巨大数値はウェイトではなく**サイズ・字間・色面**で強調する

⚠️ Windows以外の環境でHTMLを直接開く場合は `Noto Sans JP` → `游ゴシック` の順にフォールバックする。
必要になったら `BIZ UDPGothic` の woff2 を `fonts/` に置き、`@font-face` を足す（ライセンス上可）。

## 全16種に共通する規約

| # | 規約 |
|---|---|
| C1 | 🔴 **見出しは2段。** 上段＝**タイトル**（事柄の名前・体言中心）、下段＝**メッセージライン**（主張・文）。**両方をメッセージにしない／両方をトピック名にしない**（2026-08-30 改定） |
| C2 | **メッセージラインは45〜50文字・2行以内。タイトルは25文字目安・1行** |
| C3 | 「〜し、かつ〜」「、また」が入ったら**2枚に割る**（主張が2つある） |
| C4 | 敬体（です・ます）で書く |
| C5 | **定量的な主張には必ず出典行**を置く |
| C6 | ページ番号を常時表示する |
| C7 | 1枚は**60秒**で話せる量に収める |
| C8 | アクセント色（緑）は重要点にだけ。**文字色には使わない**（面と線に限定） |

### 🔴 C1 の書き方（2段見出し）

```html
<div class="s-topic">メンバーの担当範囲の変化</div>
<h1 class="s-title">メンバーは、機能を作る人から、<em>案件1本の責任を持つ人</em>になります</h1>
<div class="s-rule"></div>
```

| 要素 | 役割 | 書き方 |
|---|---|---|
| `.s-topic` | **タイトル** — そのスライドが**何についての1枚か** | 事柄の名前。**体言中心・25文字目安・1行**。「〜します」で終わる主張にしない |
| `.s-title` | **メッセージライン** — **理解してほしいこと** | 主張。**文**で書く。45〜50文字・2行以内 |
| `.s-sub` | 補足1行（任意） | 出典・前提など |

⚠️ **`.s-topic` は 2026-08-30 に追加した要素。** それ以前の資料は `.s-title` だけで作られており、**そのまま描画される**（後方互換）。
🔴 **新規に作る資料は、必ず2段で書く。** 理由と改定の経緯は `../ドクトリン.md` 原則1。
| C9 | 同じ種類の要素でフォントサイズを変えない。CSSクラスで固定する |
| C10 | 視線は左→右。**問題・現状を左、解決・変化後を右**に置く |
| C11 | スピーカーノートを併記する |
| C12 | 軽量版は `slide--lite` ＋ `lite-hide` で切り替える |

### 情報量の上限

| 要素 | 標準版 | 軽量版 |
|---|---|---|
| 箇条書き・カード | 5 | 3 |
| 表の列 | 6 | 4 |
| 表の行 | 6 | 4 |

⚠️ **上表は「各セルが1行に収まる場合」の上限である。**
🔴 **2段見出し（2026-08-30）で本文領域が約30px減ったため、折り返すセルがあると 6行でも溢れる。**
実例: 2026/8/31、出典一覧（6行・3列）が 78px はみ出した。**長い記述は表に入れず、脚注（`s-src`）へ逃がす。**
→ 行数ではなく **`fit` を通して判定する**（`検査スクリプト/README.md`）。
| 専門用語 | 初出時に1行で定義 | 使わない。相手の業務語彙に言い換える |

## 型を足す・変えるとき（Phase 9 の還元）

**商談で使ってみて分かったことだけを反映する。** 机上で型を増やさない。

- 繰り返し使えた構成 → 新しい型として追加、または既存型のバリアントに追加
- 使われなかった型 → 索引から落とす（削除はしない。使わなかった記録も資産）
- ⚠️ **T-07 は5つの型（推移・比較・構成比・ウォーターフォール・ファネル）を束ねている。**
  ウォーターフォールの使用頻度が高いと分かった時点で、**独立IDへ昇格させる**
