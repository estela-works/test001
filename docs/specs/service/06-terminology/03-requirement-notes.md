# 要件の注意点整理

## 注意点1: 用語の曖昧性

> 「カエドキPG（通常/プラス）」と「カエドキPG」の記載が混在

**対策**: 推奨表記ルール（[01-naming-rules.md](./01-naming-rules.md)）をプロジェクト内で統一する。

## 注意点2: 支払方法制御の漏れ

> カエドキ（通常）対象機種選択時にsmartあんしん補償未選択＆ドコモMAX未選択の場合は通常分割にする制御が必要

**検討事項**:
- 画面設計の要件として整理すべきか
- SPEC側で対応すべきか
- 現状カエドキ（通常）非活性条件がないため、制御追加が必要

## 注意点3: 確認モーダルの表示条件

> カエドキPG加入中かつドコモMAX未選択の場合、smart補償解除時に確認モーダルを表示

**確認が必要な点**:
- 「カエドキPG加入中」は通常版のみか、プラス版も含むか
- モーダルで提示する選択肢の具体的な内容
