## 1. 案件概要

### 1.1 案件の背景

現在、チケット詳細モーダル（`TodoDetailModal.vue`）では、チケット情報を**表示するのみ**で、編集することができない。チケットの内容を変更したい場合、一度削除して再作成する必要があり、ユーザー体験が悪い。

### 1.2 案件の目的

チケット詳細モーダルにおいて、チケット情報（タイトル、説明、開始日、期限日、担当者）を直接編集できるようにし、ユーザビリティを向上させる。

### 1.3 対象ユーザー

| ユーザー | 利用シーン |
|---------|-----------|
| タスク管理者 | チケットの内容を修正したい場合（タイトルの誤字修正、説明追加、期限変更など） |
| 一般ユーザー | 自分のチケットの詳細を更新したい場合 |

## 2. 要求一覧

### 2.1 ビジネス要求

| ID | 要求 | 優先度 | 理由 |
|----|------|--------|------|
| BR-001 | チケット詳細モーダルで情報を編集できること | 必須 | 現状は表示のみで編集不可、再作成の手間がかかる |
| BR-002 | 編集内容を即座に反映できること | 必須 | 変更後のフィードバックがないと利用者が混乱する |

### 2.2 ユーザー要求（ユーザーストーリー）

| ID | ユーザーストーリー | 対応BR | 優先度 |
|----|-------------------|--------|--------|
| US-001 | ユーザーとして、チケット詳細画面でタイトルを編集したい。なぜなら誤字修正や内容変更を簡単に行いたいから。 | BR-001 | 高 |
| US-002 | ユーザーとして、チケット詳細画面で説明を編集したい。なぜなら追加情報を後から記載したいから。 | BR-001 | 高 |
| US-003 | ユーザーとして、チケット詳細画面で開始日・期限日を編集したい。なぜならスケジュール変更に対応したいから。 | BR-001 | 高 |
| US-004 | ユーザーとして、チケット詳細画面で担当者を変更したい。なぜなら担当者の変更が発生することがあるから。 | BR-001 | 高 |
| US-005 | ユーザーとして、編集内容を保存したらすぐに画面に反映してほしい。なぜなら変更が保存されたことを確認したいから。 | BR-002 | 高 |

## 3. スコープ定義

### 3.1 スコープ内（In Scope）

| カテゴリ | 項目 | 説明 |
|---------|------|------|
| 機能 | チケット情報編集 | タイトル、説明、開始日、期限日、担当者を編集可能にする |
| 機能 | 保存機能 | 編集内容をAPIで保存 |
| 機能 | 編集モード切替 | 表示モード⇔編集モードの切り替え |
| 画面 | チケット詳細モーダル | `TodoDetailModal.vue` の改修 |
| UI | 編集フォーム | 入力フォームコンポーネント |
| UI | 保存・キャンセルボタン | 編集の確定・キャンセル操作 |

### 3.2 スコープ外（Out of Scope）

| 項目 | 見送り理由 | 将来検討 |
|------|-----------|---------|
| 案件（プロジェクト）の変更 | 影響範囲が大きいため別案件で検討 | 可 |
| 完了状態の編集 | 既存の「完了にする」ボタンで対応済み | 不可 |
| バックエンドAPI変更 | PUT /api/todos/{id} が既に存在し要件を満たす | 不可 |
| インライン編集（モーダル外） | 今回はモーダル内編集に限定 | 可 |

## 4. 機能要件

### 4.1 機能一覧

| ID | 機能名 | 概要 | 対応US | 優先度 |
|----|--------|------|--------|--------|
| F-001 | 編集モード切替 | 「編集」ボタンで表示モードから編集モードに切り替える | US-001〜004 | 必須 |
| F-002 | タイトル編集 | テキスト入力でタイトルを編集 | US-001 | 必須 |
| F-003 | 説明編集 | テキストエリアで説明を編集 | US-002 | 必須 |
| F-004 | 開始日編集 | 日付入力で開始日を編集 | US-003 | 必須 |
| F-005 | 期限日編集 | 日付入力で期限日を編集 | US-003 | 必須 |
| F-006 | 担当者編集 | セレクトボックスで担当者を選択 | US-004 | 必須 |
| F-007 | 保存処理 | 編集内容をAPIで保存し、画面を更新 | US-005 | 必須 |
| F-008 | キャンセル処理 | 編集を破棄して表示モードに戻る | US-001〜004 | 必須 |

### 4.2 画面一覧

| ID | 画面名 | パス | 概要 |
|----|--------|------|------|
| SC-002 | ToDoリスト画面（チケット詳細モーダル） | /todos | 既存モーダルに編集機能を追加 |

## 8. 受入条件

### 8.1 機能面

| 条件 | 確認方法 |
|------|---------|
| チケット詳細モーダルで「編集」ボタンをクリックすると編集モードになる | 手動確認 |
| 編集モードでタイトル、説明、開始日、期限日、担当者を変更できる | 手動確認 |
| 「保存」ボタンで変更内容が保存される | API呼び出しと画面更新を確認 |
| 「キャンセル」ボタンで編集が破棄され表示モードに戻る | 手動確認 |
| 保存後、一覧画面にも変更が反映される | 手動確認 |

### 8.2 非機能面

| 条件 | 確認方法 |
|------|---------|
| 保存処理が3秒以内に完了する | ブラウザ開発者ツールで計測 |
| 既存の表示機能・コメント機能が正常に動作する | 手動確認 |
