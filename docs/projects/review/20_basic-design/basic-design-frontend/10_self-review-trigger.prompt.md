# Phase 2A｜トリガーの整合性チェック

## 問い

> トリガー（操作契機）が既存の操作モデルと合っているか？

## 参照ノウハウ

- [03_interface-design.md](../../knowhow/03_interface-design.md) — インターフェース設計

## チェック対象

- 設計書の「〜ボタン押下で処理X実行」が、既存モーダルの操作タイミングと一致しているか
- ボタン押下時のUIフィードバック（ローディング、二重クリック防止、活性/非活性）が設計されているか

## 典型的ミス

既存が「一時選択 -> 確定ボタン」の2段階なのに、一時選択の時点をトリガーにしてしまう。

## 実行手順

### Step 1｜トリガー全抽出

レビュー対象の設計書から、すべてのトリガー（ユーザー操作 -> システム処理の対応）を抽出し、一覧化する。

```
| # | トリガー（操作） | 発火する処理 | 設計書の該当箇所 |
|---|-----------------|-------------|----------------|
| 1 | ...             | ...         | ...            |
```

### Step 2｜既存イベントハンドラとの照合

既存の同種コンポーネント・画面のイベントハンドラを確認し、操作モデル（何段階で確定するか、どのタイミングで状態変更するか）を特定する。

### Step 3｜トリガー照合表の出力

```
| # | 設計書のトリガー | 既存の操作モデル | 一致 | 備考 |
|---|-----------------|----------------|------|------|
| 1 | ...             | ...            | OK/NG | ... |
```

### Step 4｜UIフィードバック設計チェック

各トリガーに対して、UIフィードバックが適切に設計されているか確認する。

```
| # | トリガー（操作） | ローディング表示 | 二重クリック防止 | 成功フィードバック | エラーフィードバック | 設計状況 |
|---|-----------------|---------------|---------------|----------------|-----------------|---------|
| 1 | ...             | あり/なし      | あり/なし      | ...            | ...             | OK/不足 |
```

確認ポイント:
- API呼び出しを伴う操作にローディングインジケーターが設計されているか
- ボタン押下後の二重クリック防止（disabled化等）が設計されているか
- 成功時・失敗時のユーザーフィードバック（トースト、メッセージ等）が統一されているか

## 判定基準

- 全行が「一致」であればPass
- 全トリガーにUIフィードバック設計が定義されていること
- 1つでもNGがあれば、設計書を修正してから次のPhaseへ進む
