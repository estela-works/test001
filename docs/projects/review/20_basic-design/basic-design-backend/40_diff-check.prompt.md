# Phase 3｜差分チェック

## 問い

> 上流要件・最新仕様・サービス仕様・リポジトリ実装との差分で、意図しない脱落がないか？

## チェック対象

- 【観点A】上流ドキュメント（requirements.md）の決定事項が正しく反映されているか
- 【観点B】最新スペック仕様書（specs/配下）の料金・割引・キャンペーン情報が最新か
- 【観点C】サービス仕様（申込条件、適用ルール、排他制御等）が正しく反映されているか
- 【観点D】リポジトリの既存実装パターン・命名規則・データ構造との乖離がないか

## 典型的ミス

- 要件整理書では「家族割は最大10回線まで」と明記されているのに、設計書に上限が記載されていない
- スペック仕様書の料金改定が設計書に未反映
- 既存のService層の命名規則（`XxxService`）を無視して `XxxManager` と設計する

## 実行手順

### Step 1｜上流ドキュメント（requirements.md）との突合【観点A】

要件整理書の全決定事項と、設計書の対応箇所を突合する。

```
| # | 要件の決定事項 | 要件書の該当箇所 | 設計書の該当箇所 | 反映状況 | 備考 |
|---|--------------|---------------|---------------|---------|------|
| 1 | プラン種別は3種類 | US-001 | 3.2 エンティティ | OK/未反映 | ... |
| 2 | 割引は最大3つ併用可 | US-003 | 4.1 API要件 | OK/未反映 | ... |
| 3 | 税込表示が必須 | NF-001 | 5.1 非機能要件 | OK/未反映 | ... |
```

### Step 2｜最新スペック仕様書との突合【観点B】

設計書が参照しているスペック仕様書（specs/配下）が最新版かを確認する。

```
| # | 参照仕様書 | 設計書での参照版 | 最新版 | 差異 | 影響箇所 |
|---|-----------|---------------|--------|------|---------|
| 1 | 料金プラン仕様 | v2.0 | v2.1 | あり | Plan.monthlyPrice |
| 2 | 割引ルール仕様 | v1.0 | v1.0 | なし | - |
| 3 | キャンペーン仕様 | v3.0 | v3.2 | あり | Campaign.endDate |
```

### Step 3｜サービス仕様との突合【観点C】

実際のサービス提供条件が設計書に正しく反映されているか確認する。

```
| # | サービス仕様の条件 | 設計書の記述 | 反映状況 | 備考 |
|---|-----------------|------------|---------|------|
| 1 | 家族割は同一住所が条件 | ... | OK/未反映 | ... |
| 2 | キャンペーンは新規契約のみ | ... | OK/未反映 | ... |
| 3 | 割引Aと割引Bは排他 | ... | OK/未反映 | ... |
```

### Step 4｜リポジトリ実装との突合【観点D】

既存のリポジトリ実装と設計書の方針を比較し、乖離がないか確認する。

```
| # | 確認項目 | 既存実装 | 設計書の記述 | 一致 | 備考 |
|---|---------|---------|------------|------|------|
| 1 | レイヤー構成 | Controller -> Service -> Repository | ... | OK/NG | ... |
| 2 | 命名規則 | XxxService, XxxRepository | ... | OK/NG | ... |
| 3 | エラーハンドリング | @ControllerAdvice | ... | OK/NG | ... |
| 4 | レスポンス形式 | ResponseEntity<T> | ... | OK/NG | ... |
| 5 | エンティティ設計 | @Entity + JPA | ... | OK/NG | ... |
```

### Step 5｜前版との差分確認

設計書に前版が存在する場合、差分を取り、削除・変更された箇所を列挙する。

```
| # | 変更種別 | 該当箇所 | 前版の記述 | 現版の記述 | 削除意図 |
|---|---------|---------|-----------|-----------|---------|
| 1 | 削除 | ... | ... | （なし） | 意図的/要確認 |
| 2 | 変更 | ... | ... | ... | - |
```

## 判定基準

- 観点A〜Dの全項目で意図しない脱落・未反映がなければPass
- 未反映・要確認の項目がある場合は、確認・修正後に次のPhaseへ進む
