# Phase 2A｜報告書完全性チェック

## 問い

> 作業報告書に必要な項目がすべて記載されており、成果物・ビルド結果・課題が漏れなく記録されているか？

## 関連ノウハウ

| # | ノウハウ | 本Phaseでの活用 |
|---|---------|---------------|
| 01 | [要件トレーサビリティ](../../knowhow/01_requirements-traceability.md) | 成果物一覧の網羅性確認にTMの空行検出手法を適用 |
| 02 | [設計の一貫性・整合性](../../knowhow/02_design-consistency.md) | 報告書内の用語統一、図表と本文の整合確認 |
| 09 | [保守性・可読性・命名規則](../../knowhow/09_maintainability-readability.md) | 曖昧表現の排除、文書品質の5W1Hチェック |

## チェック対象

- 実装作業報告書（implementation-report.md）および テスト実装報告書（test-implementation-report.md）
- 全成果物の一覧が記載されているか
- ビルド・テスト結果が記録されているか
- 課題・残件が文書化されているか
- 設計からの逸脱が文書化されているか

## 典型的ミス

1. 作成・変更したファイルの一部が成果物一覧に記載されていない（特に設定ファイル、マイグレーション等）
2. ビルド結果が「成功」とだけ記載され、テスト実行数・成功数・失敗数の具体的な数値がない
3. 実装中に発見した課題を口頭で共有したが報告書に記載していない
4. 詳細設計からの意図的な逸脱があるのに、逸脱理由と影響範囲が記録されていない
5. 「適切に処理する」「必要に応じて対応」等の曖昧表現が残っている（→ 具体的な条件・基準を記述する）
6. 報告書内で同一概念に異なる名称を使用している（例:「ユーザー」と「利用者」の混在）

## 実行手順

### Step 1｜テンプレート項目の充足確認

報告書テンプレートの全セクションについて、記載の有無を確認する。

```
| # | テンプレートセクション | 記載有無 | 記載内容の概要 | 判定 |
|---|---------------------|---------|-------------|------|
| 1 | 案件概要 | あり/なし | ... | OK/NG |
| 2 | 成果物一覧 | あり/なし | ... | OK/NG |
| 3 | ビルド・テスト結果 | あり/なし | ... | OK/NG |
| 4 | 設計変更・逸脱事項 | あり/なし | ... | OK/NG |
| 5 | 課題・残件 | あり/なし | ... | OK/NG |
| 6 | 次フェーズへの申し送り | あり/なし | ... | OK/NG |
```

### Step 2｜成果物一覧の網羅性確認

報告書の成果物一覧を、上流の設計書（詳細設計書またはテスト仕様書）で定義された成果物と照合する。
TMの空行検出手法を適用し、対応のない成果物を機械的に検出する。

**実装作業報告書の場合:**
```
| # | 詳細設計書で定義された成果物 | 出典 | 報告書に記載 | ファイルパス | 判定 |
|---|--------------------------|------|-----------|-----------|------|
| 1 | PlanEstimateService.java | detail-design-logic.md | あり | src/main/... | OK |
| 2 | discount-master.sql | detail-design-db.md | なし | - | NG（漏れ） |
```

**テスト実装報告書の場合:**
```
| # | テスト仕様書で定義されたテスト | 出典 | 報告書に記載 | テストファイルパス | 判定 |
|---|---------------------------|------|-----------|----------------|------|
| 1 | FT-001〜FT-010 | test-spec-frontend.md | あり | src/test/... | OK |
| 2 | SI-001〜SI-005 | test-spec-backend.md | なし | - | NG（漏れ） |
```

### Step 3｜ビルド・テスト結果の記録確認

ビルド結果とテスト実行結果が具体的な数値で記録されているか確認する。

```
| # | 確認項目 | 記載内容 | 具体性 | 判定 |
|---|---------|---------|--------|------|
| 1 | ビルド結果 | ... | 成功/失敗+ログ有無 | OK/NG |
| 2 | テスト実行数 | ... | 具体的な数値 | OK/NG |
| 3 | テスト成功数 | ... | 具体的な数値 | OK/NG |
| 4 | テスト失敗数 | ... | 具体的な数値（0を含む） | OK/NG |
| 5 | カバレッジ | ... | パーセンテージ | OK/NG |
```

### Step 4｜設計逸脱・課題の記録確認

設計からの逸脱事項と、残課題が漏れなく記録されているか確認する。
逸脱にはIDを付与し、影響する上流ドキュメントへの逆方向リンクも確認する。

```
| # | 逸脱・課題の内容 | 報告書に記載 | 理由記載 | 影響範囲記載 | 上流ドキュメント更新 | 判定 |
|---|---------------|-----------|---------|-----------|-----------------|------|
| 1 | ... | あり/なし | あり/なし | あり/なし | 済/未 | OK/NG |
```

### Step 5｜文書品質の確認

報告書の記述品質を確認する。

```
| # | 確認項目 | 該当箇所 | 判定 |
|---|---------|---------|------|
| 1 | 曖昧表現（「適切に」「必要に応じて」等）がないか | ... | OK/NG |
| 2 | 用語が統一されているか（同一概念に複数名称がないか） | ... | OK/NG |
| 3 | 5W1H（誰が・何を・いつ・どこで・なぜ・どのように）が明確か | ... | OK/NG |
| 4 | 二重否定（「〜でないことはない」等）がないか | ... | OK/NG |
```

## 判定基準

- テンプレートの全項目が記載され、成果物・結果・課題が具体的に記録されていればPass
- 曖昧表現がなく、用語が統一されていればPass
- 記載漏れがある場合は、報告書を補完してから次のPhaseへ進む
