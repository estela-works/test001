# Phase 3｜差分チェック

## 問い

> 設計書の最終版、スペック仕様の最新版、リポジトリの実際の状態との差分で、報告書に意図しない脱落・不整合がないか？

## 関連ノウハウ

| # | ノウハウ | 本Phaseでの活用 |
|---|---------|---------------|
| 03 | [インターフェース設計](../../knowhow/03_interface-design.md) | API設計（エンドポイント、ステータスコード、エラーレスポンス）の差分確認 |
| 04 | [セキュリティ設計](../../knowhow/04_security-design.md) | セキュリティ関連成果物（認証・認可・バリデーション）の差分確認 |
| 05 | [パフォーマンス・スケーラビリティ](../../knowhow/05_performance-scalability.md) | 非機能要件（性能目標・キャッシュ戦略等）の反映漏れ確認 |
| 06 | [エラーハンドリング・異常系](../../knowhow/06_error-handling.md) | 異常系設計（エラーコード体系・リカバリー手順）の差分確認 |

## チェック対象

- 詳細設計書・テスト仕様書の最終版と報告書の記述が一致しているか
- specs/ 配下のスペック仕様書が最新版か
- リポジトリの実際のファイル構成・テスト結果と報告書が一致しているか
- 非機能要件（セキュリティ、パフォーマンス、エラーハンドリング）の成果物が漏れていないか

## 実行手順

### Step 1｜設計書の最終版との差分確認（観点A）

報告書が参照する設計書について、報告書作成後に変更がないか確認する。

**実装作業報告書の場合:**
```
| # | 設計書 | 報告書が参照した版 | 最新版 | 差分 | 報告書への影響 |
|---|-------|---------------|--------|------|-------------|
| 1 | detail-design-api.md | ... | ... | あり/なし | ... |
| 2 | detail-design-logic.md | ... | ... | あり/なし | ... |
| 3 | detail-design-db.md | ... | ... | あり/なし | ... |
```

**テスト実装報告書の場合:**
```
| # | 設計書 | 報告書が参照した版 | 最新版 | 差分 | 報告書への影響 |
|---|-------|---------------|--------|------|-------------|
| 1 | test-spec-unit-*.md | ... | ... | あり/なし | ... |
| 2 | test-spec-integration-*.md | ... | ... | あり/なし | ... |
| 3 | test-spec-system-*.md | ... | ... | あり/なし | ... |
```

### Step 2｜スペック仕様書との差分確認（観点B）

報告書が前提とする料金プラン・オプション・割引ルールが、最新のスペック仕様と一致するか確認する。

```
| # | スペック仕様項目 | 報告書での記述 | 最新スペック仕様 | 一致 | 備考 |
|---|--------------|-------------|---------------|------|------|
| 1 | プラン料金体系 | ... | ... | OK/NG | ... |
| 2 | 割引適用ルール | ... | ... | OK/NG | ... |
```

### Step 3｜サービス仕様との差分確認（観点C）

報告書の成果物がサービス仕様の最新要件を満たしているか確認する。

```
| # | サービス仕様項目 | 報告書での対応状況 | 最新サービス仕様 | 一致 | 備考 |
|---|---------------|----------------|---------------|------|------|
| 1 | ... | ... | ... | OK/NG | ... |
```

### Step 4｜リポジトリの実際の状態との差分確認（観点D）

報告書の成果物一覧・テスト結果を、リポジトリの実際の状態と照合する。

**ファイル構成の照合:**
```
| # | 報告書の成果物 | リポジトリの状態 | 一致 | 備考 |
|---|-------------|---------------|------|------|
| 1 | PlanEstimateService.java | 存在する | OK | - |
| 2 | DiscountMapper.xml | 存在しない | NG | 未コミットまたはパス誤り |
```

**テスト実行結果の照合:**
```
| # | 報告書のテスト結果 | 最新テスト実行結果 | 一致 | 備考 |
|---|-----------------|----------------|------|------|
| 1 | Tests run: 25, Failures: 0 | Tests run: 27, Failures: 0 | NG | テスト数が増加 |
```

### Step 5｜非機能要件関連の成果物確認

セキュリティ・パフォーマンス・エラーハンドリングに関する設計項目が、報告書の成果物として反映されているか確認する。

```
| # | 非機能要件カテゴリ | 設計書での定義 | 報告書での成果物 | 対応 | 備考 |
|---|-----------------|-------------|---------------|------|------|
| 1 | 認証・認可 | API認可チェック（detail-design-api.md） | ... | OK/NG | ... |
| 2 | 入力バリデーション | バリデーションルール（detail-design-logic.md） | ... | OK/NG | ... |
| 3 | エラーハンドリング | エラーコード体系（detail-design-api.md） | ... | OK/NG | ... |
| 4 | パフォーマンス | インデックス設計（detail-design-db.md） | ... | OK/NG | ... |
| 5 | セキュリティヘッダー | CSP等の設定 | ... | OK/NG | ... |
```

## 判定基準

- 全Stepで差分が解消済み、または意図的な差異として記録されていればPass
- 非機能要件関連の成果物が漏れなく確認されていればPass
- 未反映の差分がある場合は、報告書を修正してから次のPhaseへ進む
