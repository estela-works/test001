# Phase 2A｜要件の完全性チェック

## 問い

> テンプレートの全セクションが埋まっているか？ 要件として必要な情報が欠落していないか？

## 関連ノウハウ

- [01_要件トレーサビリティ](../../knowhow/01_requirements-traceability.md) - ID体系、双方向リンク、暗黙の要件
- [02_設計の一貫性・整合性](../../knowhow/02_design-consistency.md) - 図表と本文の整合、表記統一

## チェック対象

要件整理書（requirements.md）の各セクションが、テンプレートの意図する粒度で記載されているか。
「未定」「後で決める」のまま放置されている項目がないか。

## 典型的ミス

- ビジネス要求（BR）は書いたが、ユーザーストーリー（US）への分解を忘れている
- スコープ外（Out of Scope）を定義していないため、際限なく要求が膨らむ
- 非機能要件（性能・可用性・セキュリティ）が空欄のまま基本設計に進んでしまう
- 受入条件が曖昧で、完了判定ができない
- 暗黙の前提（業務慣行、運用ルール）が文書化されていない
- 図（業務フロー図、画面遷移図等）に描かれた要素が本文で説明されていない

## アンチパターン

| ID | アンチパターン | 説明 |
|----|-------------|------|
| AP-1 | ID振り忘れ症候群 | 途中から追加した要件にIDがない。IDの自動採番ルールを最初に決めておく |
| AP-2 | コピペ汚染 | 類似要件をコピペして修正漏れ。コピー元との差分を必ず明記する |
| AP-3 | 暗黙知依存 | 「当然わかるはず」で書かない。第三者が読んで理解できるか確認する |
| AP-4 | 過剰分割 | 1要件を細かく分割しすぎて全体像が見えない。要件グループで階層管理する |

## 実行手順

### Step 1｜テンプレートセクション充填チェック

テンプレート（`docs/projects/template/10_requirements/requirements-template.md`）の全セクションと、レビュー対象の要件整理書を突合する。

```
| # | セクション | テンプレートにあるか | 要件整理書に記載があるか | 内容が十分か | 備考 |
|---|-----------|--------------------|-----------------------|------------|------|
| 1 | 1.1 案件の背景 | あり | あり/なし | 十分/不足 | ... |
| 2 | 1.2 案件の目的 | あり | あり/なし | 十分/不足 | ... |
| 3 | 2.1 ビジネス要求 | あり | あり/なし | 十分/不足 | ... |
| ... |
```

### Step 2｜ID体系のトレーサビリティ確認

要件間のID参照が途切れていないか確認する。**双方向リンク**（上流→下流だけでなく下流→上流）も確認する。

```
| # | ビジネス要求(BR) | 対応ユーザーストーリー(US) | 対応機能(F) | 対応画面(SC) | トレース完備 |
|---|-----------------|-------------------------|------------|-------------|-------------|
| 1 | BR-001 | US-001, US-002 | F-001 | SC-001 | OK/NG |
| 2 | BR-002 | （なし） | - | - | NG: US未定義 |
```

粒度チェック:
- 要件と機能が1:Nになるのは正常。N:Mは粒度見直しのサイン
- 逆方向: 全機能(F)が必ずいずれかのUS/BRに紐づいているか（根拠のない機能がないか）

### Step 3｜暗黙の要件・前提の洗い出し

文書化されていない暗黙の前提・業務慣行がないか確認する。

```
| # | 暗黙の前提 | 文書化されているか | 該当セクション | 判定 |
|---|-----------|------------------|-------------|------|
| 1 | 業務時間内のみ利用可能 | あり/なし | 制約条件 | OK/NG |
| 2 | 日本語のみ対応 | あり/なし | 制約条件 | OK/NG |
| 3 | インターネット接続必須 | あり/なし | 前提条件 | OK/NG |
| 4 | 特定ブラウザのみ対応 | あり/なし | 制約条件 | OK/NG |
```

### Step 4｜図表と本文の整合チェック

要件整理書に含まれる図（業務フロー図、画面遷移図、構成図等）と本文の記述が一致しているか確認する。

```
| # | 図表 | 図に含まれる要素 | 本文での説明 | 整合 |
|---|------|----------------|------------|------|
| 1 | 業務フロー図 | 承認ステップ | セクションX に記述あり/なし | OK/NG |
| 2 | 画面遷移図 | 設定画面 | セクションX に記述あり/なし | OK/NG |
```

### Step 5｜必須項目の定量チェック

以下の項目が定量的に記載されているか確認する。

```
| # | チェック項目 | 状態 | 備考 |
|---|------------|------|------|
| 1 | 全BRにUSが1つ以上紐づいている | OK/NG | ... |
| 2 | 全USに機能(F)が1つ以上紐づいている | OK/NG | ... |
| 3 | 全機能に優先度が設定されている | OK/NG | ... |
| 4 | 非機能要件が1項目以上定義されている | OK/NG | ... |
| 5 | 受入条件に確認方法が明記されている | OK/NG | ... |
| 6 | スコープ外が1項目以上定義されている | OK/NG | ... |
| 7 | 用語定義にドメイン用語が含まれている | OK/NG | ... |
| 8 | 暗黙の前提が文書化されている | OK/NG | ... |
| 9 | 図表と本文の整合が取れている | OK/NG | ... |
```

## 判定基準

- 全セクションが充填済み、ID体系が双方向で途切れなく連鎖、暗黙の要件が文書化済み、図表と本文が整合、必須項目が全てOKであればPass
- 1つでもNG・不足がある場合、要件整理書を補完してから次のPhaseへ進む
