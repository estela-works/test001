# Phase 3｜差分チェック

## 問い

> 上流設計書の変更、スペック仕様の更新、リポジトリのテストコードとの差分で、テスト仕様書に意図しない脱落・不整合がないか？

## チェック対象

- 上流ドキュメント（requirements.md、detail-design-*.md）の変更がテスト仕様書に反映されているか
- specs/ 配下のスペック仕様書が最新版か
- リポジトリの既存テストコードとテスト仕様書の対応関係
- トレーサビリティマトリクスの更新状況

## 実行手順

### Step 1｜上流設計書との差分確認（観点A）

テスト仕様書が参照する上流ドキュメントについて、テスト仕様書作成後に変更がないか確認する。

**単体・結合テスト仕様書の場合:**
```
| # | 上流ドキュメント | テスト仕様書参照時点 | 現在の状態 | 差分 | テスト仕様書への影響 |
|---|----------------|-------------------|----------|------|-------------------|
| 1 | detail-design-api.md | ... | ... | あり/なし | ... |
| 2 | detail-design-logic.md | ... | ... | あり/なし | ... |
| 3 | detail-design-db.md | ... | ... | あり/なし | ... |
```

**総合・E2Eテスト仕様書の場合:**
```
| # | 上流ドキュメント | テスト仕様書参照時点 | 現在の状態 | 差分 | テスト仕様書への影響 |
|---|----------------|-------------------|----------|------|-------------------|
| 1 | requirements.md | ... | ... | あり/なし | ... |
```

差分がある場合、変更内容を確認し、テストケースの追加・修正が必要か判断する。
トレーサビリティマトリクスが存在する場合は、変更影響範囲をマトリクスで特定する。

### Step 2｜スペック仕様書との差分確認（観点B）

テスト仕様書が前提とする業務仕様が、最新のスペック仕様と一致するか確認する。

```
| # | スペック仕様 | テスト仕様書での記述 | 最新仕様での記述 | 一致 | 影響するテストケース |
|---|------------|-------------------|---------------|------|-------------------|
| 1 | {仕様項目} | ... | ... | OK/NG | ... |
| 2 | {仕様項目} | ... | ... | OK/NG | ... |
| 3 | {仕様項目} | ... | ... | OK/NG | ... |
```

### Step 3｜サービス仕様との差分確認（観点C）

業務ルール、適用条件、排他制御等のサービス仕様が正しく反映されているか確認する。

```
| # | サービス仕様項目 | テスト仕様書での記述 | 最新サービス仕様 | 一致 | 備考 |
|---|---------------|-------------------|---------------|------|------|
| 1 | ... | ... | ... | OK/NG | ... |
```

### Step 4｜リポジトリのテストコードとの差分確認（観点D）

既にリポジトリに存在するテストコードとテスト仕様書の対応関係を確認する。

```
| # | テストケースID | テスト仕様書の記述 | 対応テストコード | 状態 | 備考 |
|---|--------------|-----------------|---------------|------|------|
| 1 | FT-001       | {テスト概要}      | src/test/{ファイル名} | 実装済み | 内容一致 |
| 2 | SI-001       | {テスト概要}      | （なし） | 未実装 | 仕様書のみ |
| 3 | （なし）      | -               | src/test/{ファイル名} | 仕様書なし | 要確認 |
```

## 判定基準

- 全Stepで差分が解消済み、または意図的な差異として記録されていればPass
- 未反映の差分がある場合は、テスト仕様書を修正してから次のPhaseへ進む
