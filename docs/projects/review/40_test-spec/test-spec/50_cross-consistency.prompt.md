# Phase 4｜横断的整合性チェック

## 問い

> テスト仕様書全体（7テンプレート・3レベル）を横断して、矛盾・漏れ・不整合がないか？

## 位置づけ

テスト仕様書全体を俯瞰し、テストレベル間・テンプレート間の記述の矛盾・食い違いを検出する最終関門。
Phase 2A〜2Cで内部品質を、Phase 3で外部との差分を確認した上で、最後にテスト仕様書全体の一貫性を検証する。

## 実行手順

### Step 1｜テストレベル間のカバレッジマトリクス

要件・設計項目ごとに、どのテストレベルでカバーされているかを横断的に可視化する。

```
| # | 仕様項目 | 単体FE | 単体BE | 結合FE | 結合BE | 結合外部 | 総合 | E2E | カバー状態 |
|---|---------|--------|--------|--------|--------|---------|------|-----|----------|
| 1 | {機能名} | FT-001 | SU-001 | - | SI-001 | - | SYS-SC-001 | E2E-SC-001 | OK |
| 2 | {機能名} | - | SU-002 | - | SI-002 | - | - | - | NG（総合なし） |
| 3 | {機能名} | - | - | - | - | EXT-API-001 | SYS-SC-003 | - | OK |
```

全仕様項目が少なくとも1つのレベルでカバーされていることを確認する。

### Step 2｜テストデータの一貫性確認

異なるテストレベル・テンプレートで同じデータ項目を使用している場合、値や前提が矛盾していないか確認する。

```
| # | データ項目 | テストケースA | 値A | テストケースB | 値B | 矛盾 | 備考 |
|---|----------|------------|-----|------------|-----|------|------|
| 1 | {項目名} | FT-001 | {値}（税抜） | SYS-SC-001 | {値}（税込） | なし | 税抜/税込の違い（明記あり） |
| 2 | {項目名} | SU-002 | {値A} | SI-002 | {値B} | あり | 同一条件なのに異なる値 |
```

テストデータ一貫性のチェック:
- [ ] 同一マスタデータの値が全テストレベルで整合しているか
- [ ] 数値の税抜/税込の違いが明記されているか
- [ ] 状態依存データの初期状態が各レベルで適切か

### Step 3｜前提条件・テスト環境の一貫性確認

テストレベル間で前提条件（初期データ、環境設定等）が矛盾していないか確認する。

```
| # | 前提条件 | 単体での記述 | 結合での記述 | 総合での記述 | 矛盾 | 備考 |
|---|---------|-----------|-----------|-----------|------|------|
| 1 | DBの初期データ | モック | H2初期データ | 本番同等データ | なし | レベルに応じて適切 |
| 2 | マスタデータ件数 | {N}件 | {M}件 | {L}件 | 要確認 | 件数の差異は意図的か |
```

テスト環境の確認:
- [ ] 各レベルの環境（開発/テスト/ステージング）が明記されているか
- [ ] 環境間の差異が文書化されているか
- [ ] 外部システムのモック/スタブの前提が矛盾していないか

### Step 4｜用語・命名の統一確認

全テスト仕様書で同じ概念に異なる名称が使われていないか確認する。

```
| # | 概念 | テンプレートAでの名称 | テンプレートBでの名称 | 統一案 |
|---|------|-------------------|-------------------|--------|
| 1 | ... | ... | ... | ... |
```

### Step 5｜アンチパターンの最終確認

テスト仕様書全体にアンチパターンが残っていないか最終確認する。

```
| # | アンチパターン | 該当箇所 | 状態 | 備考 |
|---|-------------|---------|------|------|
| 1 | アイスクリームコーン（E2E過多/単体過少） | テストケース数の比率 | OK/NG | |
| 2 | ハッピーパスのみ（異常系不足） | {テスト対象} | OK/NG | |
| 3 | テストの重複（同一検証を複数レベルで実施） | {テストケースID} | OK/NG | |
| 4 | 曖昧な期待結果（「正しく表示される」等） | {テストケースID} | OK/NG | |
| 5 | テストケースの肥大化（1ケースで複数検証） | {テストケースID} | OK/NG | |
```

### Step 6｜最終サマリの出力

Phase 2A〜Phase 4の結果を統合し、最終判定を行う。

```
| Phase | 検出指摘数 | 修正済み | 残課題 | 判定 |
|-------|----------|---------|--------|------|
| 2A カバレッジ | ... | ... | ... | Pass/Fail |
| 2B テスト設計品質 | ... | ... | ... | Pass/Fail |
| 2C 整合性 | ... | ... | ... | Pass/Fail |
| 3 差分チェック | ... | ... | ... | Pass/Fail |
| 4 横断整合性 | ... | ... | ... | Pass/Fail |
| **総合判定** | | | | **Pass/Fail** |
```

## 判定基準

- 全テストレベル間で矛盾がなく、用語が統一され、カバレッジに漏れがなければPass
- アンチパターンが検出されていないこと
- 矛盾・漏れがある場合は修正してから人間レビューへ提出
