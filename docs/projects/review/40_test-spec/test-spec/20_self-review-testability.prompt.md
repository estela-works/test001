# Phase 2B｜テスト設計品質チェック

## 問い

> テストケースが独立・再現可能で、期待結果が具体的かつ検証可能か？

## チェック対象

- テストケース間の独立性（実行順序に依存しないか）
- テストデータの妥当性（同値分割・境界値分析・特殊値が正しく設計されているか）
- 組み合わせテストデータの技法選択（全組み合わせ/ペアワイズ/直交表）
- テストデータの再現性（バージョン管理、生成方法の文書化）
- モック・スタブ戦略の正しさ（テストレベルに応じた依存の扱い）
- 期待結果の具体性（曖昧な表現がないか）

## 典型的ミス

1. テストAの実行結果（DB状態）をテストBが前提にしており、単独実行すると失敗する
2. テストデータが「適当な値」で、実際の業務データと乖離している（本番では発生しないパターンでテスト）
3. 単体試験なのに外部APIやDBに実接続している（テストレベルとモック戦略の不一致）
4. 期待結果が「正しく表示されること」等の曖昧な記述で、具体的な検証値がない
5. テストデータにnull、空文字、特殊文字、最大長のケースが含まれていない
6. テストデータの生成方法やセットアップ/クリーンアップ手順が文書化されていない

## 実行手順

### Step 1｜テスト独立性の検証

全テストケースについて、前提条件・事前データを確認し、他テストへの依存がないか検証する。

```
| # | テストケースID | 前提条件 | 事前データ | 他テストへの依存 | 判定 |
|---|--------------|---------|----------|---------------|------|
| 1 | FT-001       | ...     | ...      | なし          | OK   |
| 2 | SI-001       | ...     | SI-002の結果を参照 | あり  | NG   |
```

セットアップ/クリーンアップの確認:
- [ ] テスト実行前のデータ投入手順が定義されているか
- [ ] テスト実行後のクリーンアップ手順が定義されているか
- [ ] テストの実行順序によって結果が変わらないか

### Step 2｜テストデータの妥当性検証

テストデータが同値分割・境界値分析・特殊値の原則に基づいて設計されているか確認する。

```
| # | テストケースID | テストデータ項目 | 設定値 | テスト技法 | 妥当性 | 備考 |
|---|--------------|---------------|-------|----------|--------|------|
| 1 | FT-001       | {項目名}       | {値}  | 同値分割（有効） | OK | 代表値として妥当 |
| 2 | FT-002       | {項目名}       | {値}  | 境界値    | OK   | 上限値 |
| 3 | FT-003       | {項目名}       | null  | 特殊値    | OK   | null検証 |
| 4 | MT-001       | {項目名}       | {値}  | -        | NG   | 根拠不明な値 |
```

テストデータ設計のチェック:
- [ ] 同値分割: 有効/無効クラスの代表値が選定されているか
- [ ] 境界値分析: 境界とその隣接値（min, min+1, max-1, max, max+1）が含まれているか
- [ ] 特殊値: null、空文字、半角/全角、特殊文字が含まれているか
- [ ] 日付データ: 年またぎ、月末、閏年のケースが含まれているか
- [ ] 数値データ: 0、負数、最大桁数のケースが含まれているか

### Step 3｜組み合わせテストデータの技法確認

複数パラメータが関係するテスト対象について、適切な組み合わせ技法が選択されているか確認する。

```
| # | テスト対象 | パラメータ数 | 選択技法 | 妥当性 | 備考 |
|---|-----------|-----------|---------|--------|------|
| 1 | {機能名}   | 2         | 全組み合わせ | OK | パラメータ少数 |
| 2 | {機能名}   | 5         | ペアワイズ | OK   | パラメータ多数 |
| 3 | {機能名}   | 4         | 全組み合わせ | NG | ペアワイズで十分 |
```

技法選定基準:
- パラメータ2つ以下 → 全組み合わせ
- パラメータ3つ以上 → ペアワイズ
- 多因子・多水準 → 直交表

### Step 4｜モック・スタブ戦略の検証

テストレベルに応じて、依存の扱い（モック/実結合）が正しいか確認する。

```
| # | テストケースID | テストレベル | 依存先 | 依存の扱い | レベルとの整合 | 判定 |
|---|--------------|-----------|-------|----------|-------------|------|
| 1 | FT-001       | 単体       | API   | MSWモック | 単体=モック化 | OK   |
| 2 | SU-001       | 単体       | DB    | H2実接続 | 単体なのに実接続 | NG   |
| 3 | SI-001       | 結合       | Mapper | 実結合   | 結合=実結合  | OK   |
```

### Step 5｜期待結果の具体性検証

期待結果が具体的な値・状態で記述されているか確認する。

```
| # | テストケースID | 現在の期待結果 | 具体性 | 改善案 |
|---|--------------|-------------|--------|-------|
| 1 | FT-001       | {具体的な値}と表示される | OK | - |
| 2 | FT-002       | エラーが表示される | NG | 「"{具体的なエラーメッセージ}"と表示される」 |
| 3 | E2E-001      | 正しく遷移する | NG | 「{具体的なパス}に遷移し、{具体的な要素}が表示される」 |
```

### Step 6｜テストデータの再現性確認

テストデータが再現可能な形で管理されているか確認する。

```
| # | 確認項目 | 状態 | 備考 |
|---|---------|------|------|
| 1 | テストデータがバージョン管理されているか | OK/NG | SQLスクリプト/Fixture等 |
| 2 | テストデータの生成方法が文書化されているか | OK/NG | |
| 3 | マスタデータの投入手順が定義されているか | OK/NG | |
| 4 | 本番データ使用時のマスキングルールがあるか | OK/NG/対象外 | |
```

## 判定基準

- 全テストケースが独立・再現可能で、期待結果が具体的であればPass
- テストデータが同値分割・境界値分析の原則に基づいて設計されていればPass
- 依存関係やモック戦略の不整合がある場合は、テスト仕様書を修正してから次のPhaseへ進む
