# Phase 3｜差分チェック

## 問い

> 上流設計書・仕様書・リポジトリ実装との差分で、意図しない脱落や不整合がないか？

## チェック対象

- 基本設計書の型情報と詳細設計書の型定義の差分
- API詳細設計書のスキーマとFE型定義の差分
- リポジトリ内の既存型定義ファイルと設計書の差分
- specs/ 配下の最新仕様と設計書の差分

## 典型的ミス

1. 基本設計書で定義されたデータ構造が詳細設計の型定義に反映されていない
2. API設計書のスキーマ変更がFE型に未反映
3. リポジトリにすでに存在する型定義と設計書の型定義が乖離している
4. 仕様書の更新（新プラン追加等）が型定義に未反映

## 実行手順

### Step 1｜基本設計の型情報 vs 詳細設計の型定義

basic-design-frontend.md で言及されているデータ構造・型情報と、型定義詳細設計書の定義を突合する。

```
| # | 基本設計書の記述 | 該当箇所 | 詳細設計の型定義 | 反映状態 | 備考 |
|----|----------------|---------|----------------|---------|------|
| 1 | プラン情報を表示する | 画面設計 §X | Plan型 | 反映済み | |
| 2 | ユーザーがプランを選択する | 操作フロー §X | SelectPlanRequest型 | 反映済み | |
| 3 | 見積結果を表示する | 画面設計 §X | Estimate型、EstimateDisplay型 | 反映済み/未反映 | |
| 4 | 割引条件の判定 | ビジネスロジック §X | DiscountRule型 | 反映済み/未反映 | |
| 5 | エラーメッセージ表示 | エラーハンドリング §X | ApiError型、ERROR_MESSAGES | 反映済み/未反映 | |
| ... | | | | | |
```

「未反映」の項目について、意図的な省略か漏れかを確認する。

### Step 2｜API詳細設計スキーマ vs FE型定義

detail-design-api.md の全エンドポイントのスキーマと、型定義設計書のリクエスト/レスポンス型を突合する。

```
| # | エンドポイント | APIスキーマの型名 | FE型名 | フィールド数一致 | 型一致 | nullable一致 | 差異内容 |
|----|-------------|-----------------|--------|---------------|--------|-------------|---------|
| 1 | GET /api/plans | PlanResponse | Plan | OK/NG | OK/NG | OK/NG | |
| 2 | POST /api/estimates | EstimateRequest | CreateEstimateRequest | OK/NG | OK/NG | OK/NG | |
| 3 | GET /api/options | OptionResponse | Option | OK/NG | OK/NG | OK/NG | |
| 4 | POST /api/discounts/validate | DiscountValidateReq | ValidateDiscountRequest | OK/NG | OK/NG | OK/NG | |
| ... | | | | | | | |
```

差異がある場合:
- FE側で意図的に変換（例: snake_case → camelCase）しているかを確認
- 不要なフィールドを省略（Pick/Omit）しているかを確認
- 意図しない差異は修正対象とする

### Step 3｜リポジトリ既存型定義ファイルとの比較

リポジトリ内の既存型定義ファイル（src/types/ 配下等）と、設計書の型定義を比較する。

```
| # | 既存ファイル | 既存の型名 | 設計書の型名 | 差異 | 対応方針 |
|----|------------|----------|------------|------|---------|
| 1 | types/plan.ts | Plan | Plan | フィールド追加あり | 設計書に従い更新 |
| 2 | types/plan.ts | PlanType | PlanType | 値追加あり | 設計書に従い更新 |
| 3 | types/estimate.ts | （なし） | Estimate | 新規型 | 新規ファイル作成 |
| 4 | types/api.ts | ApiError | ApiError | 差異なし | 変更不要 |
| 5 | types/user.ts | User | User | 差異あり | 要確認 |
| ... | | | | | |
```

確認観点:
- 既存型との後方互換性が維持されているか
- 既存の型を変更する場合、影響範囲が把握されているか
- 新規型ファイルの配置先が適切か

### Step 4｜specs/ 最新版チェック

設計書が参照している仕様書（specs/配下）が最新版かを確認する。

```
| # | 参照仕様書 | 設計書での参照日/版 | 最新版 | 差異 | 型定義への影響 |
|----|----------|-------------------|--------|------|-------------|
| 1 | プラン仕様書 | v1.2 (2026-01-15) | v1.3 (2026-02-28) | あり | 新プラン型追加が必要 |
| 2 | 料金体系仕様書 | v2.0 (2026-02-01) | v2.0 (2026-02-01) | なし | - |
| 3 | 割引ルール仕様書 | v1.1 (2026-01-20) | v1.2 (2026-02-15) | あり | 新割引タイプ追加が必要 |
| 4 | API仕様書 | v3.0 (2026-02-10) | v3.0 (2026-02-10) | なし | - |
| ... | | | | | |
```

「差異あり」の項目について、型定義への影響を評価し、必要に応じて設計書を更新する。

## 判定基準

- 全Stepで意図しない脱落・未反映・乖離がなければPass
- 要確認項目がある場合は、確認後に修正してから次のPhaseへ進む
