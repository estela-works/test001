# Phase 2B｜SQL正確性チェック

## 問い

> SQL構文・JOIN条件・WHERE条件が最新の仕様書（specs/）およびDB設計と正確に一致しているか？

## チェック対象

詳細設計書のSQL文が、構文的に正しく、JOIN条件・WHERE条件がDB設計のスキーマ定義・仕様書のビジネスルールと一致しているか。

## 典型的ミス

- LEFT JOINすべき箇所がINNER JOINになっており、割引未適用プランが結果から消える
- WHERE条件でキャンペーン期間の判定が `<` ではなく `<=` であるべき（仕様書の「以下」を「未満」で実装）
- GROUP BY句に集約キーの漏れがあり、意図しない集約結果になる
- サブクエリのNULL処理が未考慮で、割引なしプランの見積計算が失敗する

## 実行手順

### Step 1｜SQL構文の正確性確認

各SQLの構文要素を分解し、正確性を確認する。

```
| # | SQL ID | SELECT句 | FROM/JOIN句 | WHERE句 | GROUP BY | ORDER BY | 構文正確性 |
|---|--------|---------|-----------|---------|---------|---------|----------|
| 1 | ...    | ...     | ...       | ...     | ...     | ...     | OK/NG    |
```

### Step 2｜JOIN条件の正確性確認

各JOINの結合条件がDB設計のFK定義・リレーションと一致しているか確認する。

```
| # | SQL ID | JOIN種別 | 結合テーブル | 結合条件 | DB設計のFK定義 | 一致 | 備考 |
|---|--------|---------|-----------|---------|-------------|------|------|
| 1 | ...    | INNER   | ...       | ...     | ...         | OK/NG | ... |
```

### Step 3｜WHERE条件・ビジネスルールの照合

WHERE条件が仕様書のビジネスルール（期間判定、ステータス条件等）と一致しているか確認する。

```
| # | SQL ID | WHERE条件 | 対応するビジネスルール | 仕様書の定義 | 一致 | 備考 |
|---|--------|---------|-------------------|-------------|------|------|
| 1 | ...    | ...     | ...               | ...         | OK/NG | ... |
```

## 判定基準

- 全SQLの構文・JOIN条件・WHERE条件が正確で、仕様書のビジネスルールと一致すればPass
- 不一致がある場合は、詳細設計書を修正してから次のPhaseへ進む
