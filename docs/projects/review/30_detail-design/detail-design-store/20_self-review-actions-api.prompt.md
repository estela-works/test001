# Phase 2B｜Actions・APIエンドポイントマッピングチェック

## 問い

> ActionsのAPI呼び出し設計が最新の仕様書（specs/）およびAPI詳細設計と整合しているか？

## チェック対象

詳細設計書のActions定義（API呼び出し、state更新処理）が、最新の仕様書で定義されたAPIエンドポイント・レスポンス仕様と一致しているか。

## 典型的ミス

- 仕様書で追加された新APIエンドポイントに対応するActionが未定義
- ActionのAPI呼び出し時のリクエストパラメータが、API設計書のスキーマと不一致
- APIレスポンスの型とstateの型にミスマッチがある（例：APIはsnake_caseだがstateはcamelCase、変換処理が未設計）
- プラン見積APIの呼び出し後に、関連するStore（割引Store、キャンペーンStore）の状態更新が漏れている

## 実行手順

### Step 1｜Actions・API呼び出しの全抽出

詳細設計書から全ActionsとそのAPI呼び出し先を抽出する。

```
| # | Store名 | Action名 | 呼び出しAPI | HTTPメソッド | リクエスト型 | 更新するstate |
|---|---------|---------|-----------|------------|-----------|-------------|
| 1 | ...     | ...     | ...       | ...        | ...       | ...         |
```

### Step 2｜仕様書・API詳細設計との照合

Actions定義と仕様書・API詳細設計のエンドポイント定義を突合する。

```
| # | Action名 | API詳細設計のエンドポイント | リクエスト型一致 | レスポンス型一致 | 備考 |
|---|---------|------------------------|---------------|---------------|------|
| 1 | ...     | ...                    | OK/NG         | OK/NG         | ...  |
```

### Step 3｜Action実行後の状態更新チェーン確認

各Action実行後の状態更新が、関連する全Storeに正しく波及しているか確認する。

```
| # | Action名 | 更新するStore | 更新するstate | 関連Store への波及 | 波及漏れ |
|---|---------|-------------|-------------|-----------------|---------|
| 1 | ...     | ...         | ...         | ...             | あり/なし |
```

## 判定基準

- 全ActionsがAPI詳細設計と一致し、状態更新チェーンに漏れがなければPass
- 不一致または波及漏れがある場合は、詳細設計書を修正してから次のPhaseへ進む
