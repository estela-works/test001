# Phase 2A｜コンポーネント構造の整合性チェック

## 問い

> コンポーネント分割・Props/Emits定義が基本設計（basic-design-frontend.md）と整合しているか？

## チェック対象

詳細設計書のコンポーネントツリー、Props/Emits定義が、基本設計で定義された画面構成・データフローと一致しているか。

## 典型的ミス

- 基本設計の画面構成図にあるコンポーネントが詳細設計で欠落している
- 基本設計で親子関係として定義されたコンポーネントが、詳細設計では兄弟関係になっている
- 基本設計のデータフローで必要なPropsが詳細設計のProps定義に含まれていない
- プラン選択画面のコンポーネント分割粒度が基本設計と一致しない（例：料金表示部分を分離すべきなのに一体化している）

## 実行手順

### Step 1｜基本設計からのコンポーネント一覧抽出

basic-design-frontend.mdの画面構成・コンポーネント構成から、全コンポーネントとその親子関係を抽出する。

```
| # | コンポーネント名 | 親コンポーネント | 基本設計の該当箇所 |
|---|-----------------|----------------|-------------------|
| 1 | ...             | ...            | ...               |
```

### Step 2｜詳細設計のコンポーネント定義との照合

詳細設計書のコンポーネント定義を基本設計の一覧と突合する。

```
| # | コンポーネント名 | 基本設計 | 詳細設計 | Props一致 | Emits一致 | 備考 |
|---|-----------------|---------|---------|-----------|-----------|------|
| 1 | ...             | あり    | あり    | OK/NG     | OK/NG     | ...  |
```

### Step 3｜データフロー整合性の確認

基本設計で定義されたデータの流れ（親→子へのProps、子→親へのEmits）が詳細設計のインターフェース定義と一致するか確認する。

```
| # | データフロー | 基本設計の定義 | 詳細設計のProps/Emits | 一致 | 備考 |
|---|-------------|--------------|---------------------|------|------|
| 1 | ...         | ...          | ...                 | OK/NG | ... |
```

## 判定基準

- 全コンポーネントが基本設計と一致し、Props/Emitsの過不足がなければPass
- 1つでもNGがあれば、詳細設計書を修正してから次のPhaseへ進む
