# Phase 2C｜UX・アクセシビリティチェック

## 問い

> コンポーネントのUX設計とアクセシビリティ対応が最新のサービス仕様と整合しているか？

## チェック対象

詳細設計書のUI挙動（ローディング、エラー表示、フォーカス管理等）とアクセシビリティ対応が、サービス仕様の要件を満たしているか。

## 典型的ミス

- プラン選択画面でキーボード操作（Tab/Enter）によるプラン切り替えが考慮されていない
- 見積計算中のローディング状態表示が設計されていない
- 料金変更時のaria-live領域が定義されておらず、スクリーンリーダーで変更が通知されない
- エラーメッセージの表示位置がサービス仕様のガイドラインと異なる

## 実行手順

### Step 1｜UX要件の抽出

サービス仕様からUX関連の要件（ローディング、エラー表示、フォーカス管理、トランジション等）を抽出する。

```
| # | UX要件 | サービス仕様の該当箇所 | 対象コンポーネント |
|---|--------|---------------------|------------------|
| 1 | ...    | ...                 | ...              |
```

### Step 2｜詳細設計との照合

抽出したUX要件が詳細設計書に反映されているか確認する。

```
| # | UX要件 | 詳細設計の対応 | 対応状況 | 備考 |
|---|--------|-------------|---------|------|
| 1 | ...    | ...         | OK/NG/未記載 | ... |
```

### Step 3｜アクセシビリティチェックリスト

WAI-ARIA対応、キーボード操作、スクリーンリーダー対応を確認する。

```
| # | コンポーネント名 | aria属性 | キーボード操作 | フォーカス管理 | 対応状況 |
|---|-----------------|---------|-------------|-------------|---------|
| 1 | ...             | ...     | ...         | ...         | OK/NG   |
```

## 判定基準

- 全UX要件が詳細設計に反映され、主要コンポーネントのアクセシビリティ対応が記載されていればPass
- 未記載またはNGがある場合は、詳細設計書を修正してから次のPhaseへ進む
