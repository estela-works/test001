# Phase 2B｜状態管理・イベントハンドリングチェック

## 問い

> Store利用・イベントハンドリングが最新の仕様書（specs/）と整合しているか？

## チェック対象

詳細設計書のStore参照、イベントハンドラ定義が、最新の仕様書で定義された状態管理方針・イベント仕様と一致しているか。

## 典型的ミス

- 仕様書で追加された新しいStoreのstateを詳細設計が参照していない
- イベントハンドラの引数型が仕様書の最新型定義と不一致
- プラン変更時のイベント伝播チェーンが仕様書の規定と異なる
- 見積結果の一時保存・復元の状態管理が仕様書と食い違っている

## 実行手順

### Step 1｜Store利用箇所の全抽出

詳細設計書からStore（Pinia）を利用している全箇所を抽出する。

```
| # | コンポーネント名 | 利用Store | 参照するstate/getter | 呼び出すaction | 設計書の該当箇所 |
|---|-----------------|----------|---------------------|---------------|----------------|
| 1 | ...             | ...      | ...                 | ...           | ...            |
```

### Step 2｜仕様書との照合

specs/配下の最新仕様書と突合し、Store定義・イベント定義の整合性を確認する。

```
| # | 項目 | 詳細設計の記述 | 仕様書の定義 | 一致 | 備考 |
|---|------|-------------|-------------|------|------|
| 1 | ...  | ...         | ...         | OK/NG | ... |
```

### Step 3｜イベントハンドリングチェーンの検証

ユーザー操作から最終的な状態更新までのイベント伝播チェーンを追跡し、途切れや誤りがないか確認する。

```
| # | ユーザー操作 | イベント発火 | 中間処理 | 最終状態更新 | 仕様書との一致 |
|---|------------|-----------|---------|------------|--------------|
| 1 | ...        | ...       | ...     | ...        | OK/NG        |
```

## 判定基準

- 全Store利用箇所が最新仕様と一致し、イベントチェーンに途切れがなければPass
- 不一致または途切れがある場合は、詳細設計書を修正してから次のPhaseへ進む
