# 08. テストデータ設計・管理

テストデータの準備、境界値設計、テスト環境管理に関するノウハウ。

## なぜ重要か

- テストデータの質がテストの信頼性を直接決定する
- 本番データに近いテストデータでなければ、リリース後に想定外の問題が発生する
- テストデータの管理が不十分だと、テストの再現性が失われる

## テストデータ設計の原則

### 1. 代表値と境界値の選定

| テスト技法 | データ選定基準 | 例（年齢フィールド: 0〜120） |
|-----------|-------------|---------------------------|
| 同値分割 | 有効・無効クラスの代表値 | 有効: 25, 無効: -1, 121 |
| 境界値分析 | 境界とその隣接値 | 0, 1, 119, 120, 121 |
| 特殊値 | null、空文字、最大長 | null, "", "a"×256 |

### 2. 組み合わせテストデータ

| 技法 | 説明 | 適用場面 |
|------|------|---------|
| 全組み合わせ | すべての組み合わせ | パラメータ・値が少ない場合 |
| ペアワイズ | 2因子間の全組み合わせ | パラメータが多い場合（3つ以上） |
| 直交表 | 統計的に代表的な組み合わせ | 多因子・多水準の場合 |

### 3. 状態依存のテストデータ

状態遷移テストでは、各状態に対応するデータを準備する。

```
| テストID | 初期状態 | 操作 | 期待される状態 | テストデータ |
|----------|---------|------|-------------|------------|
| ST-001   | 下書き   | 送信 | 送信済み     | status='draft' のレコード |
| ST-002   | 送信済み | 承認 | 承認済み     | status='submitted' のレコード |
| ST-003   | 承認済み | 送信 | エラー       | status='approved' のレコード |
```

## テストデータの種類

| 種類 | 説明 | 管理方法 |
|------|------|---------|
| マスタデータ | テスト実行の前提となる固定データ | SQLスクリプトで投入、バージョン管理 |
| トランザクションデータ | テスト操作で生成・更新されるデータ | テストケースごとに準備・クリーンアップ |
| 参照データ | 外部マスタ（都道府県コード等） | テスト環境用のシードデータ |
| 大量データ | 性能テスト用の大量レコード | データ生成スクリプトで自動生成 |

## テストデータ設計のチェック観点

### データの妥当性

- [ ] テストデータが本番データの特性を反映しているか
- [ ] 境界値（最小値、最大値、上限+1、下限-1）が含まれているか
- [ ] null、空文字、半角/全角、特殊文字のデータが含まれているか
- [ ] 日付データに年またぎ、月末、閏年のケースが含まれているか
- [ ] 数値データに0、負数、最大桁数のケースが含まれているか

### データの独立性

- [ ] テストケース間でデータが共有されていないか（相互干渉の防止）
- [ ] テスト実行前のセットアップとテスト実行後のクリーンアップが設計されているか
- [ ] テストの実行順序によって結果が変わらないか

### データの再現性

- [ ] テストデータがバージョン管理されているか
- [ ] テストデータの生成方法が文書化されているか
- [ ] 本番データを使用する場合のマスキング（個人情報の匿名化）ルールがあるか

### ドメイン固有のデータ（料金計算アプリの例）

| テストデータ | 確認事項 |
|------------|---------|
| 料金プラン | 全プランのマスタデータが揃っているか |
| 割引ルール | 全割引パターンの組み合わせデータ |
| 税率 | 現行税率、軽減税率、将来の税率変更 |
| 日付 | 月初、月末、月途中、年度切替 |
| 金額 | 0円、最大金額、端数が出る金額 |

## テスト環境管理

### 環境の種類と目的

| 環境 | 目的 | データ特性 |
|------|------|-----------|
| 開発環境 | 開発者のローカルテスト | 最小限のシードデータ |
| テスト環境 | 結合テスト・システムテスト | 本番相当のデータ構造 |
| ステージング環境 | リリース前の最終確認 | 本番データのマスキングコピー |
| 性能テスト環境 | 負荷テスト | 本番相当のデータ量 |

### 環境管理のチェックポイント

- [ ] テスト環境のリセット手順が定義されているか
- [ ] テスト環境と本番環境の差異が文書化されているか
- [ ] テスト環境の構成（OS、ミドルウェアバージョン等）が管理されているか
- [ ] 外部システムのモック/スタブが準備されているか

## アンチパターン

| パターン名 | 症状 | 処方 |
|-----------|------|------|
| 本番データ直接使用 | 個人情報がテスト環境に存在 | マスキングルールを定義して適用 |
| テストデータの共有 | 1つのデータを複数テストで使い回し | テストごとに独立したデータを用意 |
| 手動データ投入 | 毎回手作業でデータを準備 | SQLスクリプト/Fixtureで自動化 |
| ハードコード | テストコードにデータが直書き | テストデータファイルとして外部化 |
