# 04. セキュリティ設計

設計書レビューにおけるセキュリティ観点のノウハウ。OWASP Top 10 2025を軸に、設計段階で防ぐべき脆弱性を整理する。

## なぜ重要か

- セキュリティの問題は設計段階で防ぐのが最もコスト効率が良い
- 実装後の脆弱性修正は10倍以上のコストがかかるとされる
- インシデント発生時の事業リスク（情報漏洩、信用失墜）は甚大

## OWASP Top 10 2025

| # | カテゴリ | 設計で考慮すべきこと |
|---|---------|-------------------|
| A01 | アクセス制御の不備 | RBAC/ABACの設計、最小権限の原則、リソース単位の認可チェック |
| A02 | セキュリティの設定ミス | デフォルト設定の見直し、不要なサービス・ポートの無効化 |
| A03 | サプライチェーンの障害 | 依存ライブラリの脆弱性管理、SBOMの整備 |
| A04 | 認証の不備 | 多要素認証、セッション管理、パスワードポリシー |
| A05 | 暗号化の失敗 | TLS 1.3の採用、機密データの暗号化、鍵管理 |
| A06 | 脆弱で古いコンポーネント | ライブラリバージョン管理、EOL製品の排除 |
| A07 | インジェクション | SQLインジェクション、XSS、コマンドインジェクション対策 |
| A08 | セキュリティログと監視の不足 | 監査ログの設計、異常検知、SIEM連携 |
| A09 | サーバーサイドリクエストフォージェリ（SSRF） | 外部リクエストのホワイトリスト、内部ネットワークの保護 |
| A10 | 安全でないリソース管理 | ファイルアップロード制限、一時ファイルの管理 |

## 認証・認可の設計レビュー

### 認証方式

| 方式 | 適用場面 | 注意点 |
|------|---------|--------|
| OAuth 2.0 + PKCE | フロントエンド認証 | Authorization Code Flow with PKCE |
| クライアントクレデンシャル | システム間連携 | アクセストークンに有効期限を設定 |
| セッション + Cookie | Web アプリ | `Secure`, `HttpOnly`, `SameSite=Lax` 必須 |
| JWT | API認証 | トークンのペイロードに機密情報を含めない |

### 認可チェックポイント

- [ ] 全APIエンドポイントに認可チェックが設計されているか
- [ ] ロールベースの権限マトリクスが定義されているか
- [ ] リソース所有者チェック（自分のデータのみアクセス可）が設計されているか
- [ ] 管理者権限の操作に追加の認証（再ログイン等）が必要か検討されているか
- [ ] 権限昇格の防止策が設計されているか

## 入力バリデーション

### バリデーション設計のポイント

| レイヤー | バリデーション内容 |
|---------|------------------|
| フロントエンド | UX向上のための即座フィードバック（信頼しない） |
| APIゲートウェイ | リクエスト形式、サイズ上限、レート制限 |
| バックエンド | ビジネスルール検証、型チェック、範囲チェック |
| データベース | 制約（NOT NULL、UNIQUE、CHECK）による最終防衛 |

### よくある脆弱性と対策

| 脆弱性 | 対策 |
|--------|------|
| SQLインジェクション | プリペアドステートメント必須。動的SQLの禁止 |
| XSS | 出力エスケープ、CSPヘッダー設定 |
| CSRF | CSRFトークン、SameSite Cookie |
| パストラバーサル | ファイルパスのホワイトリスト検証 |
| オープンリダイレクト | リダイレクト先のホワイトリスト検証 |

## セキュリティヘッダー

設計書に以下のレスポンスヘッダーの設定が含まれているか確認する。

```
Content-Security-Policy: default-src 'none'
X-Content-Type-Options: nosniff
Strict-Transport-Security: max-age=63072000; includeSubDomains
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
```

## Cookie属性

| 属性 | 必須 | 説明 |
|------|------|------|
| `Secure` | 必須 | HTTPS接続時のみ送信 |
| `HttpOnly` | 必須 | JavaScriptからアクセス不可 |
| `SameSite=Lax` | 必須 | CSRF対策 |
| `__Host-` プレフィックス | 推奨 | Secure+パス固定を強制 |
| `Max-Age` | 推奨 | 明示的な有効期限 |

## 機密データの取り扱い

| チェック項目 | 説明 |
|------------|------|
| ログ出力 | パスワード、トークン、個人情報がログに出力されないか |
| エラーメッセージ | スタックトレースや内部情報が外部に露出しないか |
| API レスポンス | 不要なフィールドが含まれていないか（過剰な情報公開） |
| データ保持 | 個人情報の保持期間・削除方針が定義されているか |
| 暗号化 | 保存時暗号化（at rest）と通信時暗号化（in transit）の両方 |

## レビュー時のチェックポイント

- [ ] OWASP Top 10の各項目に対する対策が設計に含まれているか
- [ ] 認証・認可の方式が明確に定義されているか
- [ ] 入力バリデーションが全レイヤーで設計されているか
- [ ] セキュリティヘッダーの設定が定義されているか
- [ ] 機密データの取り扱いルールが明記されているか
- [ ] 監査ログの出力項目・保存期間が定義されているか
- [ ] 脆弱性のある依存ライブラリの管理方針があるか
