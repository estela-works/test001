# プロット: エージェントAIを利用したシステム開発

## 講義の全体テーマ

エージェントAIを活用してシステム開発の生産性を飛躍的に向上させるための手法提案。
AIの能力を最大限引き出すには「適切な情報管理」が鍵であることを示し、具体的な管理手法（SPEC&Project方式）を提案する。

---

```

  ↓ （AIの仕組みを理解する）
第2章 LLMによる開発の課題

第5章 提案手法: SPEC&Project方式
  　 （具体的なアクションに落とす）
```

## 第1章: LLMの基礎

### 目的
後の章（特に第4章）の理解に必要なLLMの基礎知識を与える。

### キーメッセージ
- LLMは与えられたコンテキスト（情報）をもとに推論する
- コンテキストの質＝出力の質である
- 「何を渡すか」がAI活用の成否を決める

### 話す内容
- LLMの基本的な仕組み（トークン予測、コンテキストウィンドウ）
- プロンプトとコンテキストの関係
- 良いコンテキストとは何か：正確・一貫・最新の情報

---

## 第2章: LLMによる開発の課題

### 目的
現状のAI活用で発生している根本的な課題を浮き彫りにする。

### キーメッセージ
- AIに渡す情報が散在・重複・矛盾していると、AIの出力品質が下がる
- 根本原因は「1情報1ソース」になっていないこと

### 話す内容
- AI活用の現場で起きていること
  - 同じ情報がコード・ドキュメント・チャットに散在
  - どれが最新かわからない
  - 矛盾した情報をAIに渡してしまう
- 情報が正しく単一化されていないことが諸問題の根幹
- 「1情報1ソース」の原則と、現実とのギャップ

---

## 第3章: システム開発手法の歴史的課題

### 目的
第2章の課題がなぜ放置されてきたのか、歴史的背景から説明する。

### キーメッセージ
- システム開発は「0→完成」に最適化されてきた
- 継続的バージョンアップへの手厚いケアが手法として不足している
- 背景にはエンジニアの情報管理負荷の問題がある

### 話す内容
- 従来の開発手法は新規構築（0→完成）が主眼
  - ウォーターフォール：作り切って納品
  - 反復型でも「イテレーション内の完成」が単位
- 継続的なバージョンアップの管理が弱い
  - 仕様書は作った時点が最新、以降メンテされない
  - コードが唯一の真実になりがち
- エクストリームプログラミング（XP）の歴史的文脈
  - 「正しく管理するコスト」＞「正しく開発するコスト」という判断
  - ドキュメントより動くコードを重視する思想
  - 合理的な判断だったが、情報管理を諦めた代償がある
- 結果として、長期運用・バージョンアップに必要な情報蓄積が仕組み化されていない

---

## 第4章: AIが変える情報管理のコスト構造

### 目的
AIの登場によりパラダイムが変わったことを示す。第1章の知識がここで活きる。

### キーメッセージ
- AIにより情報の記載・更新コストが限りなくゼロに近づいている
- これまで諦めてきた詳細な情報管理が現実的になった
- そして、適切な情報管理がAIの能力をさらに向上させる（好循環）

### 話す内容
- AIによるコスト構造の変化
  - ドキュメント生成・更新をAIが担う
  - 人間の負荷が激減 → 情報管理を「諦める理由」がなくなった
- 好循環の構造（第1章の知識を活用）
  - 適切な情報管理 → 良質なコンテキスト → AIの出力品質向上
  - AIの出力品質向上 → さらなる情報管理の効率化
  - 回せば回すほど加速するフライホイール
- XPが諦めた世界を、AIが取り戻す

---

## 第5章: 提案手法 — SPEC&Project方式

### 目的
具体的な手法を提案し、聴講者に実践を促す。

### キーメッセージ
- 「最新断面の仕様（SPEC）」と「変更行為（Project）」を分離して管理する
- Projectを作り、SPECを更新し続けることで情報蓄積と管理を実現する
- これによりAIの能力を引き出し、プロジェクト全体の生産性を上げる

### 話す内容
- 2つの管理対象の定義
  - **SPEC**: システムの最新断面の仕様。常に「今の正しい姿」を反映する
  - **Project**: 変更行為の単位。何を・なぜ・どう変えたかを記録する
- 運用サイクル
  1. Projectを立ち上げる（変更の目的・スコープを定義）
  2. 設計・実装を進める
  3. 完了時にSPECを更新する（最新断面を反映）
  4. SPECは常に最新の真実として維持される
- この方式がもたらす効果
  - 1情報1ソースの実現（SPECが唯一の真実）
  - 変更履歴の構造化（Projectが変更の文脈を保持）
  - AIへの最適なコンテキスト提供 → 能力最大化
  - プロジェクト全体の生産性向上
