# スライドデザイン（本設計）: エージェントAIを利用したシステム開発

## 設計意図（タイトルとメッセージライン）

- タイトルは「そのスライドで何を判断すべきか」が一読で分かる文言にする
- メッセージラインは「1スライド1主張」で、章間で論理が連結するように設計する
- 全体は「第0章でフレーム提示 → 第1〜4章で前提/問題/転換提示 → 第5〜6章で解法提示 → クロージングで行動化」の流れ

---

|----|----|----------------|

```text
第0章: 「○○ネイティブ = 最適化対象の転換」を定義

  ↓

  ↓

  ↓

```

## 第5章（10枚）提案手法: SPEC&Project

| ID | タイトル | メッセージライン |
|----|---------|------------------|
| 5-01 | 第5章: 提案手法 SPEC&Project | 解法は大規模改革ではなく運用可能な二層構造である |
| 5-02 | 導入: 必要なのはシンプルな型 | 課題全体は2つの管理対象に分解できる |
| 5-03 | 2つの管理対象の全体像 | SPECは「今」、Projectは「変化」を担う |
| 5-04 | SPECの定義（最新断面） | SPECは常に最新である唯一の真実として運用する |
| 5-05 | Projectの定義（変更行為） | Projectは「なぜ・何を・どう変えたか」を保持する |
| 5-06 | SPECとProjectの関係 | 正しさはSPEC、文脈はProjectで保持することで両立できる |
| 5-07 | 運用サイクル（立上げ→実装→レビュー→SPEC更新→次案件） | 「Project完了時にSPEC更新」を必須ゲートにする |
| 5-08 | 品質維持の仕組み | AI下書き＋人間レビューで品質と速度を両立する |
| 5-09 | この方式の効果（課題へのアンサー） | SSOT、文脈継承、案件連続性、AI精度向上を同時達成できる |
| 5-10 | ブリッジ: 本当に効くのかを検証する | 次章で課題別に有効性を照合する |
