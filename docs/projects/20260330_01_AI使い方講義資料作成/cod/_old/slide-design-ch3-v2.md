# スライド設計: 第3章 システム開発手法の歴史的課題

## 章の役割

- 第2章で見えた課題が「怠慢」ではなく「歴史的合理性の結果」であると示す
- 開発手法の進化と情報管理の未整備を切り分けて理解させる
- 「意志の問題ではなくコスト構造の問題」という結論で第4章へ接続する

## 感情設計

怒り → 納得 → 焦り → 転換への期待

## 圧縮方針（v1→v2）

- 旧10枚→6枚。手法史の詳細より、意思決定ロジックに焦点化
- WF/Agile比較と「完成後の手薄さ」を2枚で整理
- XP/スクラムは「合理性」と「AI時代の限界」を1枚で対比
- 章末で第0章フレーム（制約→最適化）に回収して橋渡しする
