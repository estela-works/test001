# スライド設計: 第0章 AIネイティブ開発とは何か（アイスブレイク）

## 章の役割

- 講義全体のフレーム（制約→最適化対象→合理的戦略）を提示する
- 「○○ネイティブ＝新技術を使うことではない」という視点を獲得させる
- 「AIネイティブ開発で脱構築されるべき常識とは？」という問いを残し、全章への期待を作る

## 感情設計

興味 → 「知ってるつもり」への揺さぶり → パターン認識の快感 → 期待

## 圧縮方針（v1→v2）

- 旧12枚→6枚。○○ネイティブ3例のうち、ペルソナに最も近いクラウドネイティブは個別展開を維持
- インターネットN・デジタルNは比較表に集約し、口頭で補足
- クラウドNを先に詳細展開 → 比較表で他2例を追加する流れにより「パターン発見」体験を維持
- 詳細は75枚フル版（配布資料）に委譲

### 0-03: ○○ネイティブ比較表

| 項目 | 内容 |
|------|------|
| 種別 | 図解 |
| キーメッセージ | 3つの変化は同じ論理構造を持っている |
| 内容 | 3行×5列の比較表を**1行ずつ段階表示（アニメーション）**する。3行目（クラウド）で「パターンが見えますか？」と問いかけ |
| 表の構造 | 下記参照 |
| 話者ノート | 各行表示時に具体的産業変化を口頭補足。インターネット: 「出版社・TV局→YouTube・Spotify」、デジタル: 「高額市場調査→A/Bテスト」、クラウド: 「CAB・四半期リリース→CI/CD・IaC」 |
| 感情 | 1行目: 「ふむ」→ 2行目: 「あ、同じだ」→ 3行目: 「パターン確定！」 |

**表の内容:**

| 時代 | 制約の変化 | 最適化対象の移動 | 脱構造 | 再構築 |
|------|-----------|-----------------|--------|--------|
| インターネットN (1990s〜) | 配信コスト↓ | 配信制約 → 探索制約 | 配信の独占（出版社、TV局、CD小売） | 検索・レコメンド・プラットフォーム |
| デジタルN (2000s〜) | 試行コスト↓ | 期待損失最小化 → 学習速度最大化 | 高額市場調査、一発勝負型制作 | A/Bテスト、アジャイル、非同期コラボ |
| クラウドN (2010s〜) | 変更コスト↓ | 変更回数最小化 → 変更単位最小化 | 重い変更管理、モノリシック設計 | IaC、CI/CD、マイクロサービス、SRE |
