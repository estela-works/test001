Projectは1つの変更要求を分解した変更パッケージである
requirements → basic-design → detail-design → test-spec → report の流れで、今回の判断と実施を残す
10_requirements

要求整理

背景、目的、スコープ、ユーザーストーリーを定義する。

20_basic-design

基本設計

画面構成、責務分担、データ要件、API要件を切る。

30_detail-design

詳細設計

API、Logic、DB、SQL、Store、Typesまで具体化する。

40_test-spec

試験設計

unit / integration / system / e2e の観点で確認方法を決める。

50_report

実施報告

実装結果、変更ファイル、試験結果を残し、次案件が参照できる形にする。

Projectは「今の仕様」ではなく、「今回どう変えるか」と「どう実施したか」を残すための束である
Project Change Package Per Request
