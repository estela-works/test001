# スライド設計: 第3章 システム開発手法の歴史的課題

## 講義全体の目的

エージェントAIを活用したシステム開発への転換を提案する講義。
「AIネイティブ開発」とは何かをフレーム化し、現場のシステム開発手法が抱える歴史的課題を解きほぐした上で、具体的な手法（SPEC&Project）を提案し、その有効性を論証する。全6章＋クロージングの59枚構成。

## 章の目的

- 第2章の課題がなぜ放置されてきたか、歴史的背景を説明する
- 情報管理の軽視が「怠慢ではなく合理的なトレードオフ」だったことを示す（怒りの緩和）
- 「コスト構造が変われば判断も変わる」→ 第4章への伏線

## 感情設計

怒り（「なぜ放置してきた？」）→ 納得（「合理的だったのか」）→ 焦り（「でもこのままでは」）

## 圧縮方針（v1→v2）

- 旧10枚→6枚。WF/Agile対比（旧3-02）と手厚い/手薄い（旧3-03）を統合、XP（旧3-05）とスクラム（旧3-06）を統合
- WF/Agileの違いはペルソナの既知領域であるため、スライドでは「共通の盲点」に焦点を絞り、手法の違いは口頭で補足
- スクラムセレモニーの個別説明は統合スライド内のミニ表で視覚的に残す
- XP→スクラムの統合スライドでは、怒りの緩和に必要な「間」を話者ノートで指示

### 3-02: 開発手法と情報管理の盲点

**コンセプト:**

**文脈情報:**
- 講義の目的: AIネイティブ開発への転換を提案する（全59枚）

### 3-03: PJ単位の断絶

**コンセプト:**

**文脈情報:**
- 講義の目的: AIネイティブ開発への転換を提案する（全59枚）
- 章の目的: 情報管理の軽視が合理的トレードオフだった歴史的背景を説明する

- 次スライド: 3-04 XP・スクラム。なぜこの構造が放置されてきたか、合理的トレードオフとして説明する
- このスライドの役割: 盲点の帰結を「断絶の図」として可視化し、怒りを構造的問題として定着させる。次の3-04で「実はそれには合理的な理由があった」と転換するための下地を作る

| 項目 | 内容 |
|------|------|
| 種別 | 図解 |

### 3-05: 暗黙知の限界＋まとめ

**コンセプト:**
3-04で「合理的だった」と肯定した直後に、「しかしこのままでは」への転換を行う。暗黙知の4つの限界を列挙し、特に「AIに渡せない」を最後に置くことで、第4章（AIによるコスト構造変化）への布石を打つ。まとめ3点は第3章全体の論理を凝縮し、聴衆が持ち帰れる構造にする。

**文脈情報:**
- 講義の目的: AIネイティブ開発への転換を提案する（全59枚）
- 章の目的: 情報管理の軽視が合理的トレードオフだった歴史的背景を説明する
- 前スライド: 3-04 XP・スクラム。「合理的判断だった」で怒りが緩和された直後。ベテランの防衛も緩んでいる
- 次スライド: 3-06 第0章フレーム＋ブリッジ。第0章の5ステップ構造に当てはめ、第4章への遷移を作る
- このスライドの役割: 「合理的だった → しかし限界がある」への転換。暗黙知の限界を列挙し、特に「AIに渡せない」で第4章への伏線を作る。まとめ3点で第3章の論理を凝縮する

| 項目 | 内容 |
|------|------|
| 種別 | コンテンツ |
| キーメッセージ | AIは暗黙知を読めない。暗黙知で回すチーム＝AIに渡せる情報が少ないチーム。これはコストの問題であって意志の問題ではない |
| 内容 | 上段: 暗黙知の限界 — チーム外に持ち出せない、メンバー離脱で消失、スケールしない、**AIに渡せない**。下段: まとめ3点 — (1) 情報管理を後回しにしたのは合理的判断だった (2) 暗黙知で回す仕組みとして成熟した (3) しかし形式知の蓄積が仕組み化されなかった |
| ビジュアル | 人間の頭の中（暗黙知）↔ AIのコンテキストウィンドウ の断絶を図示 |
