# スライド設計: 第3章 システム開発手法の歴史的課題

## 講義全体の目的

エージェントAIを活用したシステム開発への転換を提案する講義。
「AIネイティブ開発」とは何かをフレーム化し、現場のシステム開発手法が抱える歴史的課題を解きほぐした上で、具体的な手法（SPEC&Project）を提案し、その有効性を論証する。全6章＋クロージングの59枚構成。

## 章の目的

- 第2章の課題がなぜ放置されてきたか、歴史的背景を説明する
- 情報管理の軽視が「怠慢ではなく合理的なトレードオフ」だったことを示す（怒りの緩和）
- 「コスト構造が変われば判断も変わる」→ 第4章への伏線

## 感情設計

怒り（「なぜ放置してきた？」）→ 納得（「合理的だったのか」）→ 焦り（「でもこのままでは」）

## 現在のタイトルとメッセージ

| No | タイトル | メッセージ |
|----|----------|------------|
| 3-01 | 開発手法が抱える情報管理の共通盲点 | 手法を変えても完成後の情報劣化は止められていない |
| 3-02 | 継続改修時代に薄い情報管理の手当て | 既存の開発手法は立ち上げに手厚く情報の継続更新には仕組みがない |
| 3-04 | ドキュメント軽視を生んだ時代背景 | 当時は情報管理より実装優先が合理的になるコスト構造だった |
| 3-05 | 暗黙知中心の開発が抱える構造限界 | 人には伝わる知識でもAIには渡らず再利用も広がらない |
| 3-06 | 言語化コストが旧合理性を支えた構造 | 意志でなくコストが判断を決めていたから現場は変われなかった |

## 圧縮方針（v1→v2）

- 旧10枚→5枚。WF/Agile対比（旧3-02）と手厚い/手薄い（旧3-03）を統合、XP（旧3-05）とスクラム（旧3-06）を統合。さらにPJ単位の断絶（旧3-03）は3-02に吸収して削除
- WF/Agileの違いはペルソナの既知領域であるため、スライドでは「共通の盲点」に焦点を絞り、手法の違いは口頭で補足
- スクラムセレモニーの個別説明は統合スライド内のミニ表で視覚的に残す
- XP→スクラムの統合スライドでは、怒りの緩和に必要な「間」を話者ノートで指示

### 3-02: 継続改修時代に薄い情報管理の手当て

**コンセプト:**
WFとAgileという対立的な手法が、実は「情報管理の仕組みが完成時点を想定している」という同一の盲点を共有していることを示す対比スライド。左右の対比は「手厚い領域 vs 手薄い領域」であり、WF vs Agileではない。聴衆が「手法の違い」に意識を向けがちなところを、「共通の盲点」に焦点を絞ることで、より深い構造的理解を促す。

**文脈情報:**
- 講義の目的: AIネイティブ開発への転換を提案する（全59枚）
- 章の目的: 情報管理の軽視が合理的トレードオフだった歴史的背景を説明する
- 前スライド: 3-01 章タイトル。「なぜ情報管理が軽視されてきたか」というテーマが提示された直後
- 次スライド: 3-04 ドキュメント軽視を生んだ時代背景。なぜこの構造が放置されてきたか、合理的トレードオフとして説明する
- このスライドの役割: WF/Agile共通の構造的盲点を提示し、「手法の問題ではなく構造の問題」という認識を作る。第2章の怒りに「構造的な理由があった」という方向性を与える最初のスライド

| 項目 | 内容 |
|------|------|
| 種別 | 対比 |
| タイトル | 継続改修時代に薄い情報管理の手当て（16文字） |
| メッセージ | 既存の開発手法は立ち上げに手厚く情報の継続更新には仕組みがない（26文字） |
| キーメッセージ | 新規に作る仕組みは設計されていても、育ち続ける情報の仕組みは設計されていない |
| 左カラム（手厚い領域） | 新規設計プロセス（要件定義から実装まで手順が確立されている）、テスト戦略 TDD/BDD（品質を担保する型が既にある）、リリース管理 CI/CD（ビルドから本番反映まで自動化されている） |

### 3-04: ドキュメント軽視を生んだ時代背景

### 3-05: 暗黙知中心の開発が抱える構造限界

**コンセプト:**
3-04で「合理的だった」と肯定した直後に、「しかしこのままでは」への転換を行う。暗黙知の3つの構造的限界を列挙し、最後に「AIは暗黙知を読めない」という最大の問題を提示することで、第4章（AIによるコスト構造変化）への布石を打つ。

**文脈情報:**
- 講義の目的: AIネイティブ開発への転換を提案する（全59枚）
- 章の目的: 情報管理の軽視が合理的トレードオフだった歴史的背景を説明する

- 次スライド: 3-06 言語化コストが旧合理性を支えた構造。第0章のフレームに当てはめ、第4章への遷移を作る
- このスライドの役割: 「合理的だった → しかし限界がある」への転換。暗黙知の限界を列挙し、特に「AIは暗黙知を読めない」で第4章への伏線を作る

### 3-06: 言語化コストが旧合理性を支えた構造

**コンセプト:**
