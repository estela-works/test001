# スライド設計: 第1章 LLMの基礎

## 講義全体の目的

エージェントAIを活用したシステム開発への転換を提案する講義。
「AIネイティブ開発」とは何かをフレーム化し、現場のシステム開発手法が抱える歴史的課題を解きほぐした上で、具体的な手法（SPEC&Project）を提案し、その有効性を論証する。全6章＋クロージングの59枚構成。

## 章の目的

- 後の章（特に第4章・第6章）の理解に必要なLLMの基礎知識を付与する
- 「コンテキストの質＝出力の質」という講義全体の核心命題を確立する
- 原理から活用ノウハウを演繹できることを示し、「暗記ではなく理解で戦える」感覚を与える
- 現在のAIエージェントも文脈上限から自由ではないことを示し、依頼スコープ設計の重要性へつなぐ

## 感情設計

知的好奇心 → 「仕組みがわかった」快感 → 「文脈設計で結果を変えられる」手応え → 実践意欲

**コンセプト:**

### 1-05: コンテキストウィンドウ

**コンセプト:**
「試験で持ち込み可能なカンペ」という比喩でコンテキストウィンドウを直感的に理解させる。技術用語を日常の体験に翻訳することで、非エンジニアにも伝わり、エンジニアにも「言い得て妙」と感じさせる。1-04で示した「渡す情報が全てを決める」を受けて、「ではその枠はどのくらいで、何を入れるかが本質だ」と腹落ちさせる。

**文脈情報:**
- 講義の目的: AIネイティブ開発への転換を提案する（全59枚）

### 1-06: AIエージェントでも消えない文脈上限

**コンセプト:**
1-05で学んだコンテキストウィンドウ（カンペの枠）を前提に、「エージェントなら長時間使えるから大丈夫」という誤解を具体的メカニズムで崩す。核心は、コンテキストリミットに達したときにエージェントが会話履歴を圧縮し、その要約を新しいセッションの冒頭に差し込むことで見かけ上は会話が続いているように見えるが、実際には詳細な文脈を失った別のコンテキストに入れ替わっており、それゆえ性能が劣化する、という因果の全体像である。

**文脈情報:**
- 講義の目的: AIネイティブ開発への転換を提案する（全59枚）
- 章の目的: 後の章の理解に必要なLLMの基礎知識を付与する。「コンテキストの質＝出力の質」という核心命題を確立する
- 前スライド: 1-05 コンテキストウィンドウ。「有限な枠に何を入れるかが本質」を理解した直後
- 次スライド: 1-07 依頼を小さく切る。文脈上限のメカニズムを知った上で「だから仕事を小さく切る」へ自然に接続
- このスライドの役割: セッション継続の裏側で起きている圧縮→差し込み→文脈入れ替わり→性能劣化のメカニズムを可視化し、依頼スコープ設計の必要性を腹落ちさせる

|------|------|
