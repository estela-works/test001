# 42 - 結合試験

## 目的

単体試験で個別に確認済みのモジュールを**実際に結合**し、モジュール間のインターフェースとデータの受け渡しが正しく動作することを検証する。

## スコープ定義

### 結合試験が答えるべき問い

> 「単体では正しく動くモジュール同士を繋いだとき、**接合部**で問題は起きないか？」

結合試験の焦点は**モジュール間の境界**にある。個々のモジュール内部のロジックは単体試験で保証済みとし、ここでは接合部のデータ変換・受け渡し・エラー伝播を検証する。

### 結合の3分類

```
┌─────────────────────────────────────────────────────────┐
│  42_integration-test                                     │
│                                                          │
│  ┌──────────────────┐  ┌──────────────────┐             │
│  │  フロントエンド    │  │  バックエンド      │             │
│  │  結合テスト        │  │  結合テスト        │             │
│  │                    │  │                    │             │
│  │  Component         │  │  Controller        │             │
│  │    ↕ 実結合        │  │    ↕ 実結合        │             │
│  │  Store             │  │  Service           │             │
│  │    ↕ MSW           │  │    ↕ 実結合        │             │
│  │  (API boundary)    │  │  Mapper + DB       │             │
│  └──────────────────┘  └──────────────────┘             │
│                                                          │
│  ┌─────────────────────────────────────────┐            │
│  │  外部コンポーネント接続テスト              │            │
│  │                                           │            │
│  │  自システム  ←→  外部API / 外部DB /       │            │
│  │                    MQ / 認証基盤 / ...     │            │
│  └─────────────────────────────────────────┘            │
└─────────────────────────────────────────────────────────┘
```

## 対象とするテスト

### フロントエンド結合

| 対象 | 具体例 | 確認観点 |
|------|--------|---------|
| コンポーネント + 実ストア | 画面マウント→ストアfetch→データ表示 | ストア経由のデータが画面に正しく反映されるか |
| ユーザー操作→ストア→再描画 | ボタン押下→ストアaction→画面更新 | 操作→状態変更→再描画の一連フローが動くか |
| 親コンポーネント + 子コンポーネント | Props受け渡し、Emit連携 | コンポーネント間のデータフローが正しいか |
| 画面 + Vue Router | 画面遷移、ルートパラメータ | 遷移とパラメータ受け渡しが正しいか |
| 複数ストア連携 | storeA → storeB の依存 | ストア間のデータ整合性が保たれるか |
| APIエラー→画面反映 | API 500→ストアerror状態→エラー表示 | エラー伝播が画面まで正しく届くか |

**APIの扱い**: MSW (Mock Service Worker) でモック。バックエンドは含めない。

### バックエンド結合

| 対象 | 具体例 | 確認観点 |
|------|--------|---------|
| Service + Mapper + DB | Service呼び出し→SQL実行→DB反映 | レイヤー間のデータ変換・永続化が正しいか |
| Controller + 全層 (APIテスト) | HTTPリクエスト→Controller→Service→Mapper→DB→レスポンス | REST APIとして一貫して動作するか |
| 複数Service連携 | ServiceA → ServiceB の呼び出し | Service間のトランザクション・データ整合性 |
| バリデーション→エラーレスポンス | 不正リクエスト→400応答 | バリデーションエラーが適切なHTTPレスポンスになるか |
| 存在しないリソース→404 | 不在ID→例外→404応答 | 例外がHTTPステータスに正しく変換されるか |

### 外部コンポーネント接続

| 対象 | 具体例 | 確認観点 |
|------|--------|---------|
| 外部API呼び出し | REST/gRPC通信、レスポンス処理 | 接続確立・データ送受信が正しいか |
| 外部API障害時 | タイムアウト、5xx、認証エラー | リトライ・フォールバック・エラー通知が動くか |
| 外部データストア | 外部DB・Redis・Elasticsearchへの読み書き | 接続・CRUD・障害時のハンドリング |
| メッセージング | Kafka/RabbitMQ等の送受信 | メッセージの送達・消費・順序保証 |
| ファイルストレージ | S3/FTP等のアップロード/ダウンロード | ファイル操作の正常・異常系 |
| 認証・認可基盤 | OAuth2/LDAP等の認証フロー | 認証成功/失敗、トークン管理、権限チェック |

## 対象としないテスト

| 対象外 | 理由 | 検証先 |
|--------|------|--------|
| 個々のコンポーネント/クラスの内部ロジック | モジュール内部は単体試験で保証済み | 41_unit-test |
| Props→DOM、アクション→状態変更の単体確認 | 単体試験の責務 | 41_unit-test |
| 純粋関数の入出力 | 単体試験の責務 | 41_unit-test |
| Mapper単体のSQL正常動作 | 単体試験の責務 | 41_unit-test |
| 業務シナリオ全体（複数画面をまたぐ一連操作） | ユーザー視点のシナリオは総合試験 | 43_system-test |
| フロントエンド + バックエンドの実結合 | システム全体の結合は総合試験 | 43_system-test |
| 性能テスト（応答時間、同時アクセス） | 非機能要件は総合試験 | 43_system-test |
| ユーザビリティ・アクセシビリティ | 非機能要件は総合試験 | 43_system-test |
| 障害からの復旧シナリオ全体 | リカバリシナリオは総合試験 | 43_system-test |

## よくある判断に迷うケースと指針

| ケース | 判断 | 理由 |
|--------|------|------|
| コンポーネントがストア経由でAPIを呼ぶ一連の流れ | **結合試験** | コンポーネント→ストア→API(MSW)の複数モジュール連携 |
| ストア単体でAPIモックを使ったアクションテスト | **単体試験** | ストア単体をモックAPIで検証しているだけ |
| Controller+全層でHTTPリクエスト→DBまでの検証 | **結合試験** | 複数レイヤーの実結合 |
| Service内のビジネスルール検証（Mapperはモック） | **単体試験** | Service単体をモック依存で検証 |
| 外部APIのスタブを使った接続テスト | **結合試験** | 自システム↔外部の接合部の検証 |
| 外部APIのレスポンスを使ったService内の変換ロジック | **単体試験** | 変換ロジック自体はService内部の単体問題 |
| 画面A→画面B→画面Cの業務フロー | **総合試験** | ユーザー視点の一連シナリオ |
| 画面Aから画面Bへのルートパラメータ受け渡し | **結合試験** | 2画面間のインターフェース検証 |
