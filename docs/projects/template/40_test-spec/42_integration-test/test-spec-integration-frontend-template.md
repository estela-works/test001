### 1.2 テスト方針

- **テスト範囲**: 複数のコンポーネント・ストアが**連携して**正しく動作することを検証する
- **APIの扱い**: MSW (Mock Service Worker) でAPIレスポンスを模擬し、**バックエンドは含めない**
- **単体テストとの違い**: 単体テストではモック化していたストアやコンポーネント間の連携を**実際に結合**して確認する

### 1.3 結合パターン

| パターン | 説明 | モック範囲 |
|---------|------|-----------|
| コンポーネント + ストア | コンポーネントが実ストアを使って動作するか | API通信のみMSW |
| 親コンポーネント + 子コンポーネント | Props/Emitsを介した連携が正しいか | ストア・APIをMSW |
| 画面 + ルーター | 画面遷移とパラメータ受け渡しが正しいか | API通信のみMSW |
| 複数ストア連携 | ストア間のデータ依存が正しく解決されるか | API通信のみMSW |

## 7. テスト環境

| ツール | 用途 |
|--------|------|
| Vitest | テストランナー |
| Vue Testing Library | コンポーネントレンダリング |
| MSW (Mock Service Worker) | APIモック |
| createPinia (実ストア) | ストア結合 |
| createRouter (実ルーター) | ルーティング結合 |

### 単体テストとの環境差異

| 項目 | 単体テスト | 結合テスト |
|------|----------|-----------|
| Piniaストア | `createTestingPinia`（モック） | `createPinia`（実ストア） |
| API通信 | モック関数 | MSW |
| Vue Router | モック | 実ルーター |
| 子コンポーネント | 必要に応じてスタブ | 実コンポーネント |
