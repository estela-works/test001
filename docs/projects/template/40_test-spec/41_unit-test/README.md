# 41 - 単体試験

## 目的

個々のクラス・コンポーネント・関数が**単独で**正しく動作することを検証する。

## 対象とするテスト

| 対象 | 具体例 | 確認観点 |
|------|--------|---------|
| Vueコンポーネントの描画 | Props渡し→DOM出力、条件付き表示 | 入力に対する表示の正しさ |
| コンポーネントのイベント | ボタンクリック→Emit発火 | イベント発火の正しさ |
| Piniaストアのアクション | アクション実行→状態変更 | 状態遷移の正しさ |
| Piniaストアのゲッター | 状態→算出値 | 算出ロジックの正しさ |
| 純粋関数 | 入力→出力（バリデーション、変換等） | ロジックの正しさ、境界値 |
| Mapper層のSQL | SQLクエリ→取得/挿入/更新結果 | SQL文の正しさ（H2 DB使用） |
| Service層のロジック | メソッド実行→戻り値/例外 | ビジネスロジックの正しさ |

## 対象としないテスト

| 対象外 | 理由 | 検証先 |
|--------|------|--------|
| コンポーネント + 実ストアの連携 | 複数モジュールの結合は結合試験の責務 | 42_integration-test |
| 親コンポーネント + 子コンポーネントの連携 | コンポーネント間のデータフローは結合試験 | 42_integration-test |
| API呼び出し→画面反映の一連の流れ | 複数層をまたぐフローは結合試験 | 42_integration-test |
| Service + Mapper + DB の実結合 | レイヤー間連携は結合試験 | 42_integration-test |
| Controller → Service → Mapper の全層 | APIとしての動作は結合試験 | 42_integration-test |
| 外部APIやDB等の接続確認 | 外部コンポーネント接続は結合試験 | 42_integration-test |
| 業務シナリオ全体の検証 | ユーザー視点の検証は総合試験 | 43_system-test |
| 性能・ユーザビリティ | 非機能要件は総合試験 | 43_system-test |

## 依存の扱い

**すべての外部依存をモック化する**のが単体試験の原則。

| レイヤー | 依存 | モック方法 |
|---------|------|-----------|
| コンポーネント | Piniaストア | `createTestingPinia` |
| コンポーネント | 子コンポーネント | 必要に応じてスタブ |
| ストア | API通信 | モック関数（`vi.fn()`） |
| Service層 | Mapper層 | Mockito（`@Mock`） |
| Mapper層 | DB | H2インメモリDB（SQL検証のため実DB使用） |
