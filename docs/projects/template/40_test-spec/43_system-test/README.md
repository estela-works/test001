# 43 - 総合試験

## 目的

システム全体が要件を満たしているかを、**ユーザー視点**で検証する。
単体試験・結合試験で確認済みの技術的な正しさではなく、**業務としての正しさ**を対象とする。

## 対象とするテスト

| 対象 | 具体例 | 確認観点 |
|------|--------|---------|
| 業務シナリオ | 「チケット作成→担当者割り当て→完了」の一連操作 | 業務フローが要件どおりに動作するか |
| 画面間連携 | 一覧画面→詳細画面→編集画面のデータ引き継ぎ | 複数画面をまたぐデータの整合性 |
| フロントエンド + バックエンドの実結合 | 画面操作→API→DB→画面反映 | システム全体として一貫して動作するか |
| 性能テスト | 画面表示速度、API応答時間 | 要件の基準値を満たしているか |
| ユーザビリティ | 操作の分かりやすさ、フィードバック表示 | ユーザーが迷わず使えるか |
| アクセシビリティ | キーボード操作、スクリーンリーダー対応 | 多様なユーザーが利用できるか |
| レスポンシブ対応 | タブレット・モバイルでの表示 | レイアウト崩れがないか |
| 障害・リカバリ | ネットワーク切断、セッション切れ、同時編集 | 異常状態から適切に復旧できるか |
| ブラウザバック | 戻る操作時の画面状態 | 不正な状態にならないか |
| 受入条件の検証 | requirements.md の受入条件すべて | 要件を満たしているか |

## 対象としないテスト

| 対象外 | 理由 | 検証先 |
|--------|------|--------|
| 個々のコンポーネント/クラスの動作確認 | モジュール単位の検証は単体試験 | 41_unit-test |
| レイヤー間のインターフェース検証 | 接合部の検証は結合試験 | 42_integration-test |
| 外部API/DB等への個別接続確認 | 接続レベルの検証は結合試験 | 42_integration-test |
| APIエンドポイント単位のリクエスト/レスポンス確認 | APIの技術的正しさは結合試験 | 42_integration-test |
| 2画面間のパラメータ受け渡しの技術的検証 | インターフェース検証は結合試験 | 42_integration-test |

## 総合試験の構成

```
総合試験
├── 業務シナリオテスト ─── 一部をE2E自動化 ──→ test-spec-e2e.md
├── 画面間連携テスト ──── 一部をE2E自動化 ──→ test-spec-e2e.md
├── 非機能テスト（手動）
│   ├── 性能テスト
│   ├── ユーザビリティテスト
│   └── アクセシビリティテスト
└── 障害・リカバリテスト（手動 + 一部E2E）
```

### E2Eテストとの関係

E2Eテスト（Playwright）は総合試験の**自動化パート**として位置づける。

| 項目 | 総合試験（手動） | E2Eテスト（自動） |
|------|-----------------|------------------|
| 業務シナリオ | 初回検証・探索的テスト | 繰り返し実行が必要なクリティカルパス |
| 画面間連携 | UIの見た目・使い勝手 | データ受け渡しの正確性 |
| 非機能テスト | 性能・UX・A11Y | 対象外 |
| 障害・リカバリ | ブラウザバック・同時編集 | ネットワークエラー等の再現可能なケース |

総合テスト方針書（`test-spec-system-template.md`）にトレーサビリティ表を設け、どのテストケースがE2Eで自動化されているかを管理する。
