## 1. テスト概要

### 1.1 総合テストの目的

システム全体が要件を満たしているかを、**ユーザー視点**で検証する。
単体テスト・結合テストで確認済みの個別機能ではなく、**業務シナリオとしての一連の流れ**を対象とする。

### 1.3 テスト方針

- **テスト環境**: <!-- 本番相当 / ステージング / ローカル -->
- **データ準備**: <!-- シードデータ / 手動投入 / API経由 -->
- **実施方法**: 手動テスト + E2E自動テスト（[test-spec-e2e.md](./test-spec-e2e.md)）
- **確認観点**: 機能面 + 非機能面（性能・ユーザビリティ等）

### 1.4 テスト構成

| テスト種別 | 説明 | 自動化 |
|-----------|------|--------|
| 業務シナリオテスト | ユーザーの業務フローに沿った一連操作の検証 | 一部（E2E） |
| 画面間連携テスト | 複数画面をまたがるデータの受け渡し・状態保持の検証 | 一部（E2E） |
| 非機能テスト | 性能・ユーザビリティ・アクセシビリティの検証 | 手動 |
| 障害・リカバリテスト | 異常状態からの復旧・データ不整合防止の検証 | 手動 |

## 8. E2E自動テストとの関係

総合テストのうち、自動化可能なテストケースは E2Eテスト方針書 に切り出す。

### 8.1 自動化方針

| 基準 | E2E自動化する | 手動で実施する |
|------|-------------|---------------|
| 業務シナリオ | 繰り返し実行が必要なクリティカルパス | 初回のみ・探索的テスト |
| 画面間連携 | データ受け渡しの正確性 | UIの見た目・使い勝手 |
| 非機能テスト | - | 性能・ユーザビリティ・アクセシビリティ |
| 障害・リカバリ | 一部（ネットワークエラー等） | ブラウザバック・同時編集等 |

### 8.2 トレーサビリティ
