Controller層
MockMvc / @WebMvcTest / @SpringBootTest

@MybatisTest / @SpringBootTest
SQLクエリ・データアクセス検証

レイヤー別責務

レイヤー テスト対象 モック対象 テスト種別
Controller API仕様、HTTP応答、バリデーション Service 単体 / 統合
Service ビジネスロジック、例外処理 Mapper（単体時） 単体 / 統合
Mapper SQLクエリ、データ変換 なし 統合

各レイヤーの検証項目

Controller層

  • 正常系レスポンス (200, 201)
  • エラーレスポンス (400, 404)
  • リクエストバリデーション
  • パラメータ処理

Service層

  • 期待する戻り値
  • 例外発生
  • 境界値での動作
  • 状態変化

Mapper層

  • CRUD基本操作
  • 条件検索
  • JOINマッピング
  • NULL処理

テストの書き方: AAAパターン

A
Arrange
テストデータ・前提条件を準備
A
Act
テスト対象の処理を実行
A
Assert
結果を検証
@Test
void getTodoById_正常系() {
  // Arrange
  Todo expected = todoMapper.findById(1L);

  // Act
  Todo actual = todoService.getTodoById(1L);

  // Assert
  assertThat(actual).isEqualTo(expected);
}

ベストプラクティス

推奨事項

  • AAAパターンの構造を徹底
  • 1テスト1検証の原則
  • 意味のある名前をつける
  • テストデータは最小限に
  • 統合テストを優先

アンチパターン

  • テスト間の依存関係
  • 本番DBの使用
  • 過度なモック化
  • 魔法の数値の使用
  • try-catchでの例外検証
