# WebRelease2 テンプレート実装パターン

## 基本的な構築方法

### テンプレート設計の基本方針

1. **コンポーネントの活用**: 頻出する文書構造はコンポーネントとして部品化
2. **メソッドの活用**: 再帰処理やHTML生成ロジックはメソッドに分離
3. **依存関係の活用**: 依存ページの変更時に関連ファイルを自動更新

### 構成例

```
テンプレート: ページ本体
├── コンポーネント: ヘッダー
├── コンポーネント: パンくずリスト
├── コンポーネント: サイドナビ
├── 本文（要素で定義）
└── コンポーネント: フッター
```

## パンくずリスト実装パターン

### 推奨アプローチ

パンくずリスト専用のテンプレートコンポーネントを作成する。

### 実装構造

| メソッド | 説明 |
|---|---|
| `viewBreads(target_page)` | パンくずリストのHTML出力（メインメソッド） |
| `getBreads(target_page, selector)` | 再帰的にパンくず配列を構築 |
| `getBreadATag(page)` | リンク付きパンくず要素のHTML生成 |
| `getBreadSpanTag(page)` | 現在ページ（リンクなし）のHTML生成 |

### ポイント

- 再帰関数でフォルダ階層を辿り、パンくず配列を構築
- ページIDの比較で現在ページを判定し、表示を切り替え
- 依存関係の設定により、URLの変更が自動的に反映される

## サイトマップ生成パターン

パンくずリストの再帰ロジックをJSON出力に転用することで、サイトマップを生成可能。

```html
<!-- JSON形式で出力 -->
<wr-for list="allPages()" variable="page" count="cnt">
  <wr-if condition="cnt > 1">,</wr-if>
  {"title": "%page.タイトル%", "url": "%page.url%", "level": %page.level%}
</wr-for>
```

## 条件付き出力パターン

### 要素の有無による出力制御

```html
<wr-if condition="isNotNull(サブタイトル)">
  <h2>%サブタイトル%</h2>
</wr-if>
```

### デバイス別出力（チャネル利用）

```html
<wr-if condition="channelName()==\"pc\"">
  <!-- PC向けコンテンツ -->
</wr-if>
<wr-if condition="channelName()==\"sp\"">
  <!-- スマートフォン向けコンテンツ -->
</wr-if>
```

## 一覧ページ実装パターン

### 目次要素を使った新着一覧

```html
<ul>
<wr-for list="新着一覧" variable="item" count="cnt">
  <wr-if condition="cnt <= 10">
    <li>
      <a href="%item.url%">
        %formatDate(item.公開日, "yyyy/MM/dd")% - %item.タイトル%
      </a>
    </li>
  </wr-if>
</wr-for>
</ul>
```

### フォルダ内ページの一覧

```html
<wr-variable name="pages" />
<wr-for list="folder(thisPage()).pages()" variable="p">
  <wr-append variable="pages" value="p" />
</wr-for>
```

## テキスト加工パターン

### 文字数制限付き抜粋

```html
<wr-if condition="length(本文) > 100">
  %substring(本文, 0, 100)%...
<wr-if>
  <wr-else>%本文%</wr-else>
</wr-if>
```

### 日付のフォーマット

```html
<!-- 和暦表示 -->
%gengou(公開日)%

<!-- 任意フォーマット -->
%formatDate(公開日, "yyyy年MM月dd日")%

<!-- RFC2822形式（RSS等） -->
%formatDateRFC2822(公開日)%
```

### 数値のフォーマット

```html
<!-- 3桁カンマ区切り -->
%comma3(価格)%円

<!-- 税込計算 -->
%comma3(価格 * 1.1)%円（税込）
```

## パフォーマンスに関する注意

- 数千ページを扱う場合、パンくずリストや関連ページの生成でFTP転送が遅くなる可能性がある
- 大量ページの場合は、パンくずリスト用のページを分割するか、リクエスト制限を設ける
- テンプレートプロファイラを活用してボトルネックを特定する

---

## ベストプラクティス

1. **コンポーネントの粒度**: ヘッダー・フッター・ナビゲーション等の共通部品はコンポーネント化
2. **メソッドの活用**: 再利用可能なHTML生成ロジックはメソッドに分離
3. **命名規則の統一**: 要素名・メソッド名は日本語で分かりやすく命名
4. **テスト**: テンプレートプロファイラでパフォーマンスを確認
5. **リビジョン管理**: テンプレート変更時はリビジョンを作成して変更履歴を保持
6. **チャネル設計**: マルチデバイス対応が必要な場合は、初期段階でチャネル設計を行う
