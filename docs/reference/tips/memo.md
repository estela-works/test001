### Q4 データハブの実体

1. データハブとは、具体的にどのシステム（またはDB・製品・サービス）ですか。正式名称と、提案ナビのどのレイヤー（フロントエンド・BFF・BS）から読み書きするかを教えてください。
2. データハブには、画面の選択状態をどの単位・どの形式で保存しますか（見積1件ごとのレコード、JSONの文書、キーと値など）。保存する項目の例があれば示してください。
3. 同じ見積に対して、保存の要求が続けて来た場合や、2つの端末から同時に保存された場合に、後の保存が前の保存を上書きしないようにする仕組み（版番号による条件付き更新、ロックなど）はありますか。
4. データハブへの保存をきっかけに、別の処理（BSの再計算など）を自動で動かす仕組み（イベントの通知、トリガー、キューなど）はありますか。
5. データハブのデータは、どれくらいの期間保持されますか。見積を保存して後日再開する用途や、確定した見積を監査のために残す用途に使えますか。
6. データハブの読み書きにかかる時間の目安（1回あたりのミリ秒）と、店舗全体での同時利用の規模（店舗数、1日の見積件数など）が分かれば教えてください。

### Q5 サービスマスタ（サビマ）の構造

1. サービスマスタ（サビマ）の正式名称と、提供の形（DBを直接読むのか、APIで取るのか、定期的にファイルで受け取るのか）を教えてください。
2. サビマには、料金プラン・通話オプション・各種オプション・割引・特典・端末のうち、どれが入っていますか。それぞれを表すテーブル（またはエンティティ）の名前と、主な項目を教えてください。
3. 割引の適用条件（対象の料金プラン、契約種別、年齢、継続利用年数、家族の回線数、光回線の契約の有無など）は、サビマのどの項目で表されていますか。条件が「すべての対象に当てはまる」ことと「未設定」とを、どう区別していますか。
4. 割引どうしの併用できない組合せ、ある割引が別の割引より優先される関係、一緒に付く連動の関係は、サビマに項目として入っていますか。入っていない場合、その情報はどこ（申込処理システムの規則、別のマスタ、コードなど）にありますか。
5. 金額（月額・割引額）と、その有効期間（いつからいつまでの料金か）は、サビマでどう持っていますか。料金改定の前後の値を同時に持てますか。
6. 端末について、「特殊端末」の区分や、「ドコモMAX関連割引」のようなグループ分けを表す項目はサビマにありますか。サビマの更新の頻度と、更新を担当する部署やチームも分かれば教えてください。

### Q6 既存の契約情報の取得元

1. 店舗で見積を作るとき、顧客の既存の契約情報を取得できるシステムの正式名称と、取得の方法（API、画面連携など）を教えてください。
2. そのシステムから、次の項目は取得できますか。それぞれの項目名も教えてください。年齢（または生年月日）、契約名義（個人・法人）、ドコモの継続利用年数、ahamo の契約期間（連続か通算か）、ファミリー割引グループの音声回線数。
3. 同じく、次の項目は取得できますか。ドコモ光・home 5G・ドコモでんきの契約の有無、支払いに設定しているdカードの種別（一般・GOLD 等）。
4. 過去に適用された割引の履歴（割引の種類、適用の開始日と終了日）は取得できますか。特に、U22割のような再適用できない割引や、乗りかえ向けの端末割引を前回いつ適用したかが分かりますか。
5. 最新の購入機種と、その購入日は取得できますか（機種変更の端末割引の条件「最新の購入機種の利用期間が12か月以上」の判定に使います）。
6. 取得した値はいつ時点のものですか（即時か、前日の締めか）。一部の項目が取得できない場合、項目ごとにどのような応答（空、エラーコードなど）が返りますか。
